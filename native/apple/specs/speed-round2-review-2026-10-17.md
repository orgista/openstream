**Verdict: FIX** (two required, three optional). The core claims hold: the parser memo is thread-safe and bounded, a credential can't bypass the scrub, the share and Top 10 sharing can't deadlock, and the record-id cache key matches what the id depends on. Two things in the image pipeline need fixing before ship.

**Required**

1. `Sources/OpenStreamApple/AppleArtworkDiskCache.swift:101` — once the cache reaches 512 MB, every `store` calls `trimIfNeeded()` inline on the actor. `evictionOrder` (line 22) evicts only down to `<= limit`, so the very next write is over again and triggers another full directory enumeration with `resourceValues` for every file. On a full cache that is several thousand stats per poster, serialised on the same actor that `AppleRemoteImage` now awaits for `colour(for:)` and `data(for:)`, so every tile load stalls behind it. Fix: evict to a low-water mark, e.g. pass `limit: AppleArtworkDiskCachePolicy.maximumBytes * 7 / 8` into `evictionOrder` in `trimIfNeeded`, and keep the inline call guarded by `totalBytes > maximumBytes`. Add a test that a store after trim does not need another trim.

2. `Sources/OpenStreamApple/AppleDiscoverView.swift:2416-2440` — `prefetchRequests` re-implements `AppleCatalogCard.cardWidth` (lines 3047-3088: 400, 480, 230, 320, the scaled 140-220/180-240 clamps, the 9/16 and 1.5 ratios). If either side drifts, prefetch decodes the wrong bucket and the tile decodes again, which silently defeats item 6. Anti-slop "duplicates" and "magic numbers". Fix: move the width rule to one `static func width(style:, rowStyle:, scaledCardWidth:, viewportWidth:) -> CGFloat` on `AppleCatalogShelfPolicy` (or a nonisolated static on `AppleCatalogCard`), call it from both `cardWidth` and `prefetchRequests`, and have `prefetchSelectsOnlyNextRowAndMatchesTileRequest` assert the non-fixed path too (currently it only checks the `fixedPixelDimension` branch).

**Optional, ship without them if time is short**

3. `Sources/OpenStreamApple/AppleNetflixTop10.swift:80-83` and `AppleNetworkShare.swift:633` — the shared work now lives in an unstructured `Task`, so a cancelled caller sits in `await .value` until the download or connect finishes (45 s request timeout; `manager.timeout = 8`). The two `try Task.checkCancellation()` calls inside `download(now:)` (lines 121, 128) can no longer fire. Acceptable for a shared result, but say so in a one-line comment on `inFlight` and remove the two dead checks, or wrap the waits in `withTaskCancellationHandler` that cancels the shared task only when the last waiter leaves.

4. `Sources/OpenStreamApple/AppleArtworkPrefetchPolicy.swift:10-13` — `nextRow(after:in:)` is a generic wrapper around `rows[index + 1]` with a bounds check, one call site. Inline it at `AppleDiscoverView.swift:1397` and drop the three `#expect`s on it.

5. `Sources/OpenStreamApple/AppleDiscoverView.swift:2476-2487` — first-paint prefetch decodes 20 posters for this row plus 20 for the next, per section, with no dwell. On iPhone at 3x a poster is the 512 bucket (about 1.5 MB decoded), so ten sections ask for roughly 300 MB against the 160 MB `NSCache` limit and the cache churns. The DevTV gain is measured, the iOS cost is not. Cap first-paint to the visible count (about 8) and leave 20 for the dwell pass, or measure once on DevPlus before shipping.
