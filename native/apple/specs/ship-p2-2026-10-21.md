## Review text
**VERDICT: ship.** No crash, data-loss, layout-loop, platform-guard or Release-only breakage found in the diff. `OPENSTREAM_ADDONS` is untouched, every `#if DEBUG` addition has no `#else` dependency, iOS 26 APIs (`glassEffect`, `UIButton.Configuration.glass()`) are availability-gated, and tvOS-reaching changes are limited to the health button and an unchanged Live stage path. Findings below are quality items, none blocking build 19.

**P2 — Settings now downloads and parses every Live playlist on appear.** `Sources/OpenStreamApple/AppleChannelHealthStore.swift:91-121` (network call at line 109). `prepareLineupIfNeeded` used to be cache-only. It is still called from the health rows' `.task`, so any Live source with an empty channel cache (first run, or a provider that is currently failing) triggers a full M3U/Xtream import on every Settings visit, concurrently with the Live tab's own import of the same source, and writes a validation success or failure onto the source (`recordValidationSuccess/Failure` persist). A failing provider gets a fresh failure stamped each time Settings opens. Fix: keep the `.task` path cache-only (`allowsNetwork: false`) and let only the explicit Check Channels Now button fetch.

**P2 — First launch of build 19 shows the Discover skeleton over rails that build 18 drew at once.** `Sources/OpenStreamApple/AppleDiscoverView.swift:255-256`, `1971-1973`. `showsLoadingContent` now hides existing cached sections while `recommendationsRevision == nil && discoverIsLoading`. The recommendation cache type `discover-v1` is new, so every user's first launch misses it, and `discoverIsLoading` includes `library.isLoading` and `catalogIsStillLoading`. Rails stay hidden until the first rebuild runs, which waits for `loadedCache` (index load + progress projection). On a large index that is a visible skeleton where content used to show. Fix: gate the skeleton on `!hasContent` only, or on `!hasRecommendations && heroes-would-exist`, not on the library/catalog loading flags.

**P2 — Landing hero lost its 440 pt floor; title page kept it.** `Sources/OpenStreamApple/AppleHomePhoneHeroLayout.swift:49-55`. `artHeight` is now `max(0, min(target, peekLimit))`. On a 667 pt phone (SE/8 class) `peekLimit` is roughly 667 − 83 − 90 − 62 − 40 = 392 pt, while the same title's page hero via `AppleTitlePageSlotArt.heroHeight` is 467 pt. The "unified" hero therefore differs by ~75 pt between Discover and the title page on small phones, and the trailer cover crops differently. Fix: apply the same floor, or lower `minimumArtHeight` for both, and accept a smaller row peek.

**P3 — A cancelled Library reload throws away a completed scan.** `Sources/OpenStreamApple/AppleLocalLibraryStore.swift:547`, `:572`. New `guard !Task.isCancelled` returns after "library scans done" without publishing. The Library tab's `.task` owns the reload when it starts one; switching tabs during a long NAS scan now discards the finished file list, and the next visit rescans from zero because `groups.isEmpty`. Before the change the groups were still published. Fix: run the store reload in a store-owned `Task` (or `withTaskCancellationHandler`) so view disappearance stops the eager metadata loop but not the publish.

**P3 — Widget timeline reloads twice per publish, first without art.** `Sources/OpenStreamApple/AppleTopShelfSnapshot.swift:599` saves before the hero artwork fetch, and `save()` at `:670-678` always calls `notify()` → `WidgetCenter.reloadAllTimelines()`. The medium/large widget renders the text-only hero, then re-renders with the backdrop seconds later. Fix: a `save(_:to:notify: false)` for the first write.

**P3 — Recommendation cache silently never hits for some setups.** `Sources/OpenStreamApple/AppleDiscoverRecommendationCache.swift:80-82`. `restore` requires every cached item's `sourceID` to be in `sourceStore.sources.filter(\.isEnabled)`. If any Continue Watching/pick item carries a synthetic source (media server, Xtream library shelf), the whole answer is rejected and the launch takes the old path with no trace saying why. Verify with a server user; if synthetic sources are possible, drop only those items instead of the whole answer.

**P3 — Double metadata resolve on the local title page.** `Sources/OpenStreamApple/AppleLocalLibraryStore.swift:1151-1154`. The new `.task(id: group.id)` resolves while the store's eager loop may resolve the same group; two lookups, both write `metadata[group.id]`. Harmless, but gate on `library.isLoading` or dedupe in `resolve`.

**P3 — tvOS focus nudge on Check Channels Now.** `Sources/OpenStreamApple/AppleChannelHealthViews.swift:187-202`. The button now disables during `isPreparingLineup`; on tvOS a focused button that disables hands focus to a neighbour, and on first use the prep may now hit the network (the cache-only `.task` prepare is skipped on tvOS). Previously the button only disabled during playback. Fix: keep it enabled and ignore re-presses while preparing.

Checked and clean: media index progress serialization (generation guard prevents stale re-apply; repository writes stay authoritative, `load()` after a projection self-heals); My List toggle path; detail page `VStack` swap; `ApplePhoneHeroChrome` keeps opacity-only title transitions (no layout feedback); `AppleReloadGate` begin/wait has no suspension gap; widget decode sizes fit the 30 MB extension limit; M3U parsing stays off main (`parseM3UOffMain`).
