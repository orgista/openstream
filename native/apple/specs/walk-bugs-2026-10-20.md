## Fable review (2026-10-20 15:30) — FIX FIRST
1. **Double scan on a first launch, `AppleMediaSourceViews.swift:3452`.** The Library tab's `.task` calls `reload()` when `groups` is empty. With the old `guard !isLoading` that call was dropped while the root scan ran. Now it waits on the gate and then runs a second full scan (file walk, dated items, index writes) right after the first finishes, since the gate hands off to every waiter. This hits exactly the bug-1 scenario (no persisted index, Library tab visible during the scan) and, with a root rescan also queued, can run a third. Normal launches with a persisted index are unaffected because `groups` is non-empty. Fix: `if library.groups.isEmpty && !library.isLoading { await reload() }` (the running scan will publish; `.refreshable` keeps its forced path).
2. **tvOS Settings › Live TV now fetches playlists on appear, `AppleChannelHealthViews.swift:167-170`.** `prepareLineupIfNeeded` runs from the summary line's `.task`, which on tvOS lives inline in `AppleTVLiveTabPane` (`AppleSettingsViews.swift:485`), not on a user-chosen page as on iOS/macOS (`.health` route, `#if !os(tvOS)`). Opening that pane before Live now downloads every enabled IPTV playlist, and repeats on each appearance while the fetch keeps failing, since `lineup` stays empty. Spec asked for the load "before deciding there is nothing to check", i.e. the button path. Suggest keeping the appear-time `.task` cache-only (previous behaviour) and fetching only from the button, or at least gating the `.task` fetch off tvOS.
3. **Rapid source changes serialize cleanly but repeat work, `AppleLocalLibraryStore.swift:498`.** The root `.task(id:)` cancels the prior waiter (its `waitUntilIdle` returns false, no leak) and the running scan exits at the next source boundary, so there is no starvation or overlap. Each cancel does discard every source already scanned in that pass and wipes the in-flight source's index to `.failed` (line 516, pre-existing), so an iCloud burst of six changes costs up to six partial scans. Acceptable; noted so it is not mistaken for a bug.
4. **Validation summary counts raw channels, `AppleChannelHealthStore.swift:111`.** Uses `channels.count` where Live uses the reconciled count (`AppleMediaSourceViews.swift:722`), so the source row can show a different number depending on which screen loaded it. Use the reconciled array's count.
5. **Test covers the hand-off, not the mid-scan cancel, `AppleLocalLibraryTests.swift:224`.** The probe blocks in the eager metadata phase, after the first reload has already published `groups`, so the cancel is observed at the post-resolve guard, not inside the scan loop the spec describes. It still proves the gate ordering and fails pre-fix. Low priority.
