### 1.3 How the pieces meet today (the failure modes item 7 is about)

- **A rename, a move between shares or re-adding a source is a new identity.** The local playback id is derived from
  `sourceUUID + relativePath` (`S/AppleMediaIndex.swift:528–530`), the match record and metadata cache from
  `relativePath + sizeBytes` per source (`S/AppleLibraryMetadataResolver.swift:91–93`). The progress blob is keyed by
  the hash of that id. Nothing links the old key to the new one, so progress, watched ticks, removals and the manual
  match all silently detach. (Source-level inference; not reproduced.)
- **Versions and parts are a sort order, not a model.** A dated film with two files is one group whose `items` are
  sorted best-resolution-first (`S/AppleLibraryShelves.swift:51–60`); `localFiles(for:)` re-sorts by `part` then
  resolution (`S/AppleLocalLibraryStore.swift:505–513`); `nextPart(after:)` chains only an explicit consecutive
  `cd/disc/part N` marker in the same release string (`S/AppleLibraryShelves.swift:12–25`). Each **file** has its own
  playback id (`playbackID(file)`), so a 1080p and a 4K copy keep separate progress and separate watched ticks, and
  two parts keep two resume points. The Continue Watching row then picks the file with the newest activity
  (`S/AppleLocalLibraryStore.swift:263–282`).
- **Plex versions are flattened away.** `ApplePlexItem.parts` concatenates every `Media`'s parts (`S/ApplePlexClient.swift:186–187`),
  so a 4K + 1080p item becomes a two-"part" list and `parts.first` is whichever Plex listed first. There is no
  `Media` id, no codec/bitrate/resolution, no stream list and no multi-part boundary.
- **Jellyfin/Emby has version ids but no decision.** `MediaSource.id` is used for the stream URL and reported back as
  `mediaSourceID` (`S/AppleMediaServerLibraryStore.swift:1129–1133`, `:804`), which is the correct Jellyfin 12 scope
  (Muse 99 §Jellyfin). But the request sends no device profile (`S/AppleMediaServerLibrary.swift:542–548`), so the
  server cannot say what would need transcoding, and a source that is only `SupportsTranscoding` is rejected as
  `.unsupported` (`S/AppleMediaServerLibraryStore.swift:1115–1117`).
- **The media index flattens show/season/episode.** `AppleMediaKind` has `.series` and `.episode` but local ingestion
  writes every file as `.video` (`S/AppleMediaIndex.swift:531`), and there is no parent link on `AppleMediaRecord`
  (`:50–68`). Episode membership is reconstructed on every launch from filenames (`S/AppleLocalLibraryStore.swift:27–41`).
- **Progress has one "part" dimension and it is overloaded.** `ApplePlaybackProgress.partID` means "which episode of
  the show" (`S/ApplePlaybackStore.swift:10–15`); there is nowhere to say "which version of this title" or "which
  physical part of this version". Jellyfin 12 and Kodi both needed that second axis (Muse 99 rules 4 and 6).

### 1.4 Playback decision today (item 8)

- **Engine choice is global, not per media.** `ApplePlaybackEngineFactory.make` builds Aether or, if construction
  throws, the AVPlayer-only engine (`S/ApplePlaybackEngineFactory.swift:13–32`). `ApplePlaybackEngineFallback`
  only changes the engine when the viewer forced Native and no candidate is stock-playable, and retries on Aether
  when every stream failed on Native (`S/ApplePlaybackEngineFallback.swift:32–61`). The container test is an
  extension list (`S/ApplePlaybackCoordinator.swift:591–595`).
- **Aether decides the presentation route after load, and reports it.** `VideoRoute` maps to `.avPlayer`
  (remote bypass or loopback remux), `.surface` (software decode) or `.audioOnly` (`S/AetherPlaybackEngine.swift:931–938`);
  the trace line at `:328` prints route, decoder and audio codecs; `displayTrace`/`outputInfo` report source and
  rendered dynamic range (`:672–702`). None of this is recorded as a decision with reasons that the app or a test can
  inspect before load.
- **Local/SMB files bypass inspection on the OpenStream engine.** `prepareLibraryMedia` returns `.direct` immediately
  when the preferred engine is `.openStream` (`S/ApplePlaybackPreparer.swift:102–104`); only the Native path runs
  `AppleAssetInspector` and `ApplePlaybackRoutePolicy` (`:105–122`, `S/ApplePlaybackRoute.swift:52–90`). MKV/TS are
  always `.direct` (`:65–67`). The gateway transcode route exists (`S/ApplePlaybackPreparer.swift:164–192`) and is
  owner-configured, not negotiated.
- **Plex: original part, no server decision.** `playbackRequest` builds `directPlayURL(part)` with the token in the
  query (`S/AppleMediaServerLibraryStore.swift:1070–1073`; `S/ApplePlexClient.swift:487–491`). No
  `/video/:/transcode/universal/decision`, no `X-Plex-Client-Profile-Extra`, no bitrate limit.
- **Jellyfin/Emby: direct play or direct stream, else refuse** (above).
- **Fixture coverage.** `ApplePlaybackEngineFallbackTests`, `AppleMediaServerLibraryStoreTests`,
  `AppleMediaServerTitleProgressTests`, `ApplePlexClientTests`, `AppleRemoteProgressOutboxTests`,
  `ApplePlaybackConvergenceTests`, `AppleCompletionPolicyTests`, `AppleMediaIndexTests`, `AppleLocalLibraryTests`,
  `AppleMetadataResolverTests` exist (`Tests/OpenStreamAppleTests/`). None covers a version choice, a multi-part
  chain, a transcoding-only Jellyfin source, or a Plex decision request.

## 2. Target model

Three layers, each with its own identity, and an alias table that keeps every existing key valid.

```
AppleLogicalItem            the thing the viewer thinks of: a film, a show, an episode
  id: String                "li:" + stable key (below)
  kind: movie | series | episode
  parent: AppleLogicalItem.ID?        episode -> series (season number is data, not identity)
  canonicalIDs: [AppleCanonicalID]    imdb, tmdb, tvdb, plexGUID, jellyfinProviderIds — ordered by trust
  title, year, season?, episode?, airDate?
  aliases: Set<String>                every storage key that ever meant this item (see §3.1)

AppleMediaVersion           one playable rendition of a logical item
  id: String                "mv:" + source-scoped key (below)
  item: AppleLogicalItem.ID
  sourceID: AppleSource.ID
  label: String                        "4K", "1080p", "Director's Cut", filename stem
  kind: resolution | edition | duplicate | unknown
  descriptors: AppleStreamDescriptors  container, video codec/profile/level/dynamicRange, audio tracks (codec,
                                       channels, language), subtitle tracks (format, language), bitrate, duration
  parts: [AppleMediaPart]              >= 1, ordered; stack = one version, N parts
  providerVersionID: String?           Plex Media.id / Jellyfin MediaSource.id, verbatim
  lastVerified: Date

AppleMediaPart
  id: String                           "mp:" + hash(version id + ordinal)
  ordinal: Int
  duration: Double?
  reference: String                    the EXISTING availability.itemReference / file.id / Plex part.key — opaque
```

**Stable key rules** (what `id` is built from, so that two devices and two launches agree):

| Kind | Logical item key | Version key |
|---|---|---|
| Catalog / add-on title | the IMDb or Xtream id it already uses (`AppleMediaIngestion.catalogRecord`, `S/AppleMediaIndex.swift:494–511`) | n/a (streams are transient) |
| Local file, matched | `canonicalIDs.first` (imdb > tmdb) + kind; episode = series key + `:<season>:<episode>` or `:d<airDate>` | `sourceUUID + sha256(relativePath)` (same inputs as today's record id) |
| Local file, unmatched | today's record id (`sha256("canonical\|…")`) — unchanged, it *is* the logical item until a match arrives | same |
| Plex | `ms:<src>:<ratingKey>` — unchanged | `ms:<src>:<ratingKey>:m<Media.id>`; parts from `Part.id`/`Part.key` |
| Jellyfin / Emby | `ms:<src>:<itemID>` — unchanged | `ms:<src>:<itemID>:s<MediaSource.id>` |
| Download | the download's `record.mediaID` — unchanged (`S/AppleOfflineMediaStore.swift:4–14`) | `dl:<record.mediaID>` |

Design decisions taken from Muse 99 (sourced, unverified) and the Plex report, stated as ours:

1. **Watched and Continue Watching are per logical item** (Plex/Jellyfin/Infuse model; reject Kodi's per-file
   count). Marking any version watched marks the item. This is already how `partID` works for series; it becomes
   the rule for versions too.
2. **Resume keeps two scopes:** the item's most recent position (what Continue Watching shows and what Play uses
   when no version is chosen) and a per-version position. Playing version V prefers V's own position if it is the
   freshest; otherwise it takes the item position and, if V's duration differs by more than 2 % from the duration
   the position was saved against, asks before applying it ("Resume from 1:12:03?", naming the version it came
   from). Time-based transfer only; never percentage mapping.
3. **Editions are versions within the item** for local files and Jellyfin/Emby. For Plex they stay separate items,
   because the server keeps separate watched state for them; we mirror the server and do not merge.
4. **A multi-part stack is one version with one timeline.** Position is cumulative; the player maps it to
   (part ordinal, offset) using part durations; one resume bookmark; parts chain without a prompt.
5. **Default version = most suitable, then sticky.** First play picks by the negotiation in §4; an explicit choice
   from "Other Sources" is remembered per item (`openstream.playback.preferredVersion.v1`, see §3.1) and wins until
   the viewer changes it or the version disappears. Changing the default never moves watched state.
6. **Server sources own state** (Infuse's Direct Mode rule, already our `prefersServer`):
   `S/AppleMediaServerLibraryStore.swift:750–754` stays the arbiter; the logical layer does not add a second one.
7. **Transport references stay out of the index.** `AppleMediaPart.reference` is the already-hashed
   `itemReference`/`file.id`/`part.key` — never a URL, path or token (keeps `S/AppleMediaIndex.swift:32–33` true).

`AppleMediaRecord` is **not** replaced. It gains two optional fields (`logicalItemID: String?`,
`parentLogicalItemID: String?`), both decoded as nil from existing files, so `media-index-v1.json` stays at
`version: 1` and an older build keeps opening it (the version gate at `S/AppleMediaIndex.swift:172–177` would
otherwise lock an older build out).

## 3. Staged migration

Every stage ships on its own, can be switched off by a build-time flag or a stored flag, and leaves every blob
listed in §1.2 readable by the previous build. **No stage rewrites an existing blob's keys.** New facts go in new
keys; old keys are read through the alias table. This is the same trick the store already uses for the terminals
blob as a migration marker (`S/ApplePlaybackStore.swift:697–735`) and for the legacy positional episode alias
(`S/AppleLocalLibraryStore.swift:564–597`).

### 3.1 Stage A — identity alias table and logical ids (no behaviour change)

**What ships:** `AppleIdentityAliasStore` (new file), a blob at
`openstream.identity.aliases.v1` = `[canonicalStorageKey: [aliasStorageKey]]` plus a reverse map rebuilt in memory.
`ApplePlaybackStore` gets one new read path: every lookup by storage key first tries the key, then each alias,
and merges with `ApplePlaybackConvergence.freshest` / `ApplePlaybackTerminalEvents.merging` (both already exist,
`S/ApplePlaybackStore.swift:69–78`, `:59–64`). Writes go to the **canonical** key only.

**How each stored key maps**

| Key | Stage A behaviour |
|---|---|
| `progress.v1`, `activity.v1`, `watched.v1`, `unwatched.v1`, `continueWatchingRemoved.v1`, `terminals.v1` | Unchanged on disk. Read: canonical key ∪ aliases, merged freshest/latest. Write: canonical key. A later `markUnwatched` on the canonical key tombstones the alias too (the alias's watched date is older by construction, so `AppleWatchedHistory.merge` at `S/AppleConfigurationSnapshot.swift:17–30` already yields the right answer). |
| `partID` inside progress | Unchanged: still the raw episode media id. Alias resolution applies to it the same way (`ApplePlaybackConvergence.eventKeys` already derives the part's storage key, `:118–121`). |
| `availableEpisodes.v1` | Unchanged; keyed by the show's canonical key. Alias lookup on read. |
| `remote-progress.outbox.v1` | Untouched. Entries are keyed by `sourceID + itemID`, both unchanged. |
| `media-index-v1.json` | Two optional fields added per record (§2). Version stays 1. |
| Match records | Untouched. A second lookup path is added: by `logicalItemID` when a file's own record is missing (so a renamed file inherits the manual match of the item it resolves to, provided its parsed title+year or explicit id matches). |
| `LibraryGroups-v1.json`, `MediaServers-v1.json` | Untouched (both are rebuildable caches). |
| Configuration snapshot | Gains `identityAliases: [String: [String]]` as an **optional** field (older readers ignore it; `CodingKeys` already decode optionals as absent, `S/AppleConfigurationSnapshot.swift:129–162`). Merge = union of alias sets. Cloud export counts it against `maximumCloudBytes`; trim oldest aliases first, never the canonical key's own state. |

**Where aliases come from in Stage A** (all computed, none decoded):

- Local file whose match record carries an explicit id: alias `sha256:<digest(today's playbackID)>` → canonical
  `sha256:<digest("li:" + imdb/tmdb key)>`. Recorded at the moment the match is read or saved
  (`AppleLibraryMetadataResolver.saveMatch`, `S/AppleLibraryMetadataResolver.swift:161–173`).
- Local episode positional alias: the pair already computed in `completedEpisodeIDs` (`S/AppleLocalLibraryStore.swift:572–580`)
  is written into the table once, so the three-store lookup there collapses to one.
- Catalog titles, server items, downloads: canonical = today's key. No alias needed.

**Reversible:** delete the alias blob; every read falls back to today's behaviour, because nothing was moved.

**Keeps:** progress, watched, terminals, removals (read-through), outbox (untouched), match overrides (untouched),
Continue Watching (`AppleContinueWatchingResolver.inProgress` and `AppleLocalLibraryStore.continueWatching` call the
same store functions, which now alias-resolve; the row's inputs do not change shape).

### 3.2 Stage B — versions and parts for local files and Jellyfin/Emby

**What ships:** `AppleMediaVersion`/`AppleMediaPart` built **in memory** from existing inputs — the group's sorted
`items` (`S/AppleLibraryShelves.swift:49–62`), `nextPart(after:)` (`:12–25`), parser `version`/`part`
(`S/AppleLibraryTitleParser.swift:15–16`, `:75–76`), the engine's probe for local inspection
(`AppleLocalLibraryStore.inspection(for:)`, `S/AppleLocalLibraryStore.swift:163–179`), and Jellyfin's
`mediaSources` (`S/AppleMediaServerLibrary.swift:286–318`). Persisted only as a cache
(`Caches/OpenStream/MediaVersions-v1.json`), never as user state.

Two new user-state blobs, both optional and both `[storageKey: …]` like the others:

| New key | Value | Purpose |
|---|---|---|
| `openstream.playback.versionProgress.v1` | `[itemStorageKey: [versionID: ApplePlaybackProgress]]` | the per-version resume scope (§2 rule 2). The item-level entry in `progress.v1` remains the one Continue Watching reads. |
| `openstream.playback.preferredVersion.v1` | `[itemStorageKey: versionID]` | sticky explicit choice (§2 rule 5). |

**Mapping of existing keys:** today each local **file** has its own playback id. In Stage B the file's id becomes
the **version** id and the item's canonical key (Stage A) becomes the progress key. Concretely, on first read of a
title with N files: for each file, its old progress entry (if any) is copied into `versionProgress[item][version]`
and the freshest of them becomes the item-level entry under the canonical key; the old per-file keys become aliases.
The copy is idempotent (freshest wins) and the old entries are not deleted, so a downgrade sees them unchanged.
Watched ticks: the item's tick = max over its files' ticks (already the effective rule because the row showed the
file with the newest activity). Removals: the item's removal = max over files'.

**Multi-part:** `nextPart(after:)` already yields the chain; Stage B stores the stack as one version whose parts
carry ordinal and probed duration, and the player's progress writer saves cumulative position under the version.
`AppleNextEpisodeContext` (the existing one-successor handoff, Plex report §8) is reused for the part boundary with
no prompt and no "next episode" title; the handoff guard stays.

**Jellyfin/Emby:** `playbackRequest` reports `mediaSourceID` already; Stage B records the chosen `MediaSource.id` as
the version id and saves `versionProgress` under it, which is exactly what Jellyfin 12 attributes by
(Muse 99: "Clients must send MediaSourceId in reports"). Nothing changes on the wire.

**Reversible:** delete the two new blobs and the cache; Stage A aliases keep every file's progress reachable.

**UI:** the title page's "Other Sources" list becomes the version list (same rows, now labelled by `label` and the
probed badges from `AppleStreamFormatBadges`). No new screen, no picker on Play (owner rule: stock look, no explainer
text). A long-press / "…" menu entry "Play version…" only where there is more than one version.

### 3.3 Stage C — Plex versions, GUIDs and parent links

**What ships:** `ApplePlexItem` decodes `Media[]` as versions (`id`, `videoCodec`, `videoResolution`, `bitrate`,
`audioCodec`, `audioChannels`, `container`, `videoProfile`, `Part[].id/key/duration`, and `Stream[]` for
audio/subtitle language and codec). The flattened `parts` array stays as a computed property (`versions.flatMap`)
so every current caller compiles. The catalog mapper forwards `imdbID`/`tmdbID` into `AppleCatalogItem.imdbID`
(the field already exists on the item; `S/AppleMediaServerLibraryStore.swift:351–362` passes nil today), and
`AppleMediaRecord.canonicalID` for Plex records is set to the IMDb id when present, with the `ms:` id kept as an
alias. This is the point at which a Plex film and the same film in a local folder become **one** logical item in
Continue Watching, via the Stage A alias table.

`toMediaServerItem` (`S/AppleMediaServerLibraryStore.swift:939–974`) stops requiring both `viewOffset` and
`viewCount` to build `userData` (Plex report §4 finding: a `viewCount` with no offset loses watched state).

**Mapping:** `ms:<src>:<ratingKey>` stays the item key (no alias needed). The ticket's `mediaSourceID` (today
`part.key`, `:1079`) becomes the Plex `Media.id`; the outbox ignores it for Plex (`:804` sends `""`), so pending
entries are unaffected. Plex editions remain separate items (§2 rule 3): no alias is written between two
ratingKeys even when their GUIDs agree, because the server tracks them separately.

**Reversible:** the decoder change is additive; dropping it returns to the flattened parts.

### 3.4 Stage D — index parent links and episode records

**What ships:** local ingestion writes `kind: .episode` records with `parentLogicalItemID` for files whose parse has
season/episode or an air date and whose group is a show; the show gets one `.series` record. `AppleMediaKind` and
the search eligibility (`S/AppleMediaIndex.swift:330–342`) already accept `.episode`. `episodeCandidates`
(`S/AppleLocalLibraryStore.swift:27–41`) reads the index instead of re-parsing filenames each launch; the parse
remains the fallback when the index is stale (`isStale` on availability, `:34`).

**Mapping:** today's `.video` records keep their ids; the new episode records use the Stage A logical key, so the
`.video` record's id is recorded as an alias of the episode record. `replace(instanceID:)` keeps merging favourite,
progress and privacy by id (`S/AppleMediaIndex.swift:250–265`); alias merging is added there for the transition
only. Index file version stays 1 (older builds show the extra records as plain `.episode`/`.series` entries, which
they already know how to list).

**Reversible:** the ingestion flag off writes `.video` again; alias reads keep state.

### 3.5 Stage E — Stage B/C/D on by default; alias table compaction

Only after two TestFlight rounds with no "lost my place" report. Compaction = drop aliases whose canonical key has
been written since the alias was created **and** whose aliased blobs carry nothing newer; never during the first
read after an upgrade. Downgrade after E is still possible: the old keys were never deleted, only ignored.

## 4. Playback negotiation (item 8)

### 4.1 The decision record

Every play produces one `ApplePlaybackDecisionRecord` before load, carried on `ApplePlaybackRequest.hints`
and logged by the existing trace (`AppleInteractionTrace`), so a test and the trace reader see the same object:

```
struct ApplePlaybackDecisionRecord
  item: logical id, version: version id, part ordinal
  video:    .originalBytes | .localRemux | .localSoftwareDecode | .serverRemux | .serverTranscode(maxBitrate)
  audio:    .passthrough(codec) | .localDecode(codec) | .serverTranscode(codec)
  subtitle: .embedded(trackID) | .external(trackID) | .serverBurnIn | .none
  reasons: [ReasonCode]          // why anything is not .originalBytes/.passthrough/.embedded
  transport: .file | .smbRange | .http(direct) | .gatewaySession | .serverStream
  provider: .none | .plex(decisionTimedOut: Bool) | .jellyfin(playSessionID)
  observed: (route, decoder, dynamicRange)   // filled AFTER load from AetherPlaybackEngine route/outputInfo
```

`ReasonCode` is a closed enum: `containerNotNative`, `videoCodecUnsupported(codec)`,
`videoLevelAboveHardware(level)`, `dolbyVisionProfileUnsupported(profile)`, `audioCodecUnsupported(codec)`,
`subtitleFormatNeedsConversion(format)`, `bitrateAboveRouteLimit(bps, limit)`, `remoteRoute`, `providerDecision`,
`providerDecisionTimeout`, `engineUnavailable`, `viewerOverride`.

### 4.2 Rules, in order, with the reason for each

1. **Original bytes on the OpenStream engine first.** Local, SMB and Plex direct-part URLs go to Aether as they are
   (today's `.direct` at `S/ApplePlaybackPreparer.swift:102–104`). Reason: Aether already remuxes MKV/TS on device
   and falls to software decode when it must (`mapRoute`, `S/AetherPlaybackEngine.swift:931–938`); the owner's
   2026-10-01 decision ("native player with our engine") stands. Muse 125's test list (MKV never to AVPlayer, DV
   profile 7 falls to HDR10 base layer, TrueHD decoded to LPCM) describes what Aether must already do; the decision
   record only **names** it. We do not duplicate Aether's remux pipeline (Plex report rank 8).
2. **Capability check before the request, not after the failure.** `AppleStreamDescriptors` (from the engine probe
   for local files, `Media/Stream` for Plex, `MediaSource.MediaStreams` for Jellyfin) is compared against a static
   `AppleDeviceCapabilities` table: containers Aether demuxes; HEVC up to Main 10 L5.1 hardware (Muse 125, Apple
   HLS spec, unverified for every device — a probe at first launch records the real answer); DV profiles 5 and 8
   render as DV, 7 as HDR10, others SDR; AV1 only where the SoC decodes it; audio: AAC/AC-3/E-AC-3/FLAC/ALAC
   native, TrueHD/DTS → local decode to LPCM. A mismatch yields a reason code, never an early refusal: the result
   is still "play the original; expect software decode / LPCM", which is what happens today, now written down.
3. **Jellyfin/Emby: ask with a real profile.** `playbackInfo` sends a `DeviceProfile` built from the same
   capability table plus `MaxStreamingBitrate` from the route (§4.3). Selection order: `SupportsDirectPlay` →
   `SupportsDirectStream` → `TranscodingUrl` only when a reason code is present (codec, level, DV profile or
   bitrate). Reason: today a source that is only transcodable throws `.unsupported`
   (`S/AppleMediaServerLibraryStore.swift:1115–1117`); with a profile the server tells us exactly which stream is
   the problem. Audio/subtitle choices are independent: if only the audio needs conversion, request
   `AudioStreamIndex` transcode with video copied, not a full transcode.
4. **Plex: decide only when needed, with a bound.** If the chosen `Media` has no reason codes, play the part
   directly (today). If it has any, call `/video/:/transcode/universal/decision` with
   `directPlay=1&directStream=1`, a `X-Plex-Client-Profile-Extra` that adds only the limitation named by the
   reason code, and an 8 s timeout. On a decision that says direct play is fine, play the original; on a decision
   that returns a transcode session, use `/video/:/transcode/universal/start.m3u8` as an HLS request
   (`nativeRemoteHLS`-style route, token as header not query); on timeout or error, play the original and record
   `providerDecisionTimeout`. Reason: the packaged web client has the same local fallback (Plex report finding 17);
   a timeout must never block Play.
5. **Version choice.** Among a logical item's versions: the viewer's sticky choice if present and available; else
   the highest quality with zero reason codes; else the highest quality whose only reasons are local-decode
   (software video or LPCM audio); else the version the provider can convert; else the first. "Quality" = resolution,
   then dynamic range, then bitrate (reuses `AppleStremioCandidateRanking.resolution`).
6. **Route limits.** `.smbRange` and `.file`: no bitrate cap. `.http(direct)` to a server on another network
   (`ApplePlexConnection.local == false`, `S/ApplePlexClient.swift:17–24`): default cap 20 Mb/s, overridable in
   Settings › Playback (a single stepper, stock look); a cap above the version's bitrate is a no-op; below it is a
   `bitrateAboveRouteLimit` reason that routes to rule 3/4. Reason: a 4K remux over a relay connection stalls today
   with no explanation.
7. **Fallbacks, bounded and ordered.** (a) Aether load fails on the original → if the provider offers a
   conversion, retry once with rule 3/4 forced (`reasons += engineFailure`); (b) the conversion fails → next
   version by rule 5; (c) nothing left → the existing "Playback Unavailable" alert with the decision record's
   reasons in the trace (not in the alert; owner rule: no explainer text). The engine-construction fallback
   (`ApplePlaybackEngineFactory`) is unchanged and recorded as `engineUnavailable`. Each fallback is one hop;
   `alreadyFellBack` semantics from `ApplePlaybackEngineFallback.afterEveryStreamFailed` apply
   (`S/ApplePlaybackEngineFallback.swift:53–61`).
8. **Multi-part.** Parts are negotiated once per version (the stack must share a stream layout, as Plex requires);
   a per-part surprise (second part has a different audio codec) is a `ReasonCode` on the part and triggers rule 7a
   for that part only.
9. **Diagnostics distinguish transport, local work and remote work.** The post-load `observed` triple comes from
   the engine (`route`, `activeVideoDecoder`, `outputInfo.dynamicRange`); a mismatch between the decided
   `video` outcome and the observed route is logged as `decisionMismatch` so the capability table can be corrected
   from traces. SMB range delivery is `transport`, never a video outcome (Plex report §7: "Do not claim SMB range
   delivery proves transcoding").

### 4.3 What is explicitly not done

- No client-side transcoding, no new engine, no VLCKit/mpv (Muse 125's licence findings are noted; AetherEngine's
  dynamic-framework LGPL shape already ships).
- No change to the owner-configured gateway route; it stays a manual transport for files the engine cannot open.
- No automatic quality ladder for add-on streams (that is `AppleStremioCandidateRanking`'s job and stays).

## 5. Risks

| Risk | Where | Mitigation |
|---|---|---|
| Alias read fan-out slows the hot paths that were just fixed (N34/N47: `storageKey` cache, terminals fingerprint; `S/ApplePlaybackIdentity.swift:23–29`, `S/ApplePlaybackStore.swift:739–766`) | Stage A | aliases resolved once per store instance into a `[String: String]` reverse map; fingerprint includes the alias blob; benchmark the title page with 5 000 aliases before enabling. |

| A wrong automatic match (Muse 65 lists many) now merges the wrong files' history | Stage A/B | only matches with `isManual` or `confidence >= 0.95` (exact year, `S/AppleLibraryMetadataResolver.swift:170`) create aliases; a 0.6 match keeps the file's own key. Correcting a match re-points the alias and leaves the wrong item's state alone. |
| Plex editions merged by GUID | Stage C | rule §2.3: never alias two ratingKeys. |
| Cloud snapshot grows past `maximumCloudBytes` (`S/AppleConfigurationSnapshot.swift:68`) | Stage A | aliases trimmed first in `cloudData()`; local and backups complete. |
| Downgrade after the per-version copy | Stage B | old per-file keys untouched; downgrade sees exactly the pre-upgrade state plus any newer writes under the canonical key, which the old build simply does not read (it will show the older position — acceptable, documented). |
| Device profile too strict → Jellyfin transcodes when it did not need to | §4.3 | profile only names capabilities we have a reason code for; everything else is `*`. Fixture: a direct-playable source must still come back `SupportsDirectPlay`. |
