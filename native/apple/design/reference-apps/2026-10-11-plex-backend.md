# Plex backend and features

Static REA deep dive, worker B, 2026-10-11. Targets: Plex Media Server 1.43.4.10903 and Plex's packaged web client 4.160.0 on Dev-Mini. Nothing was launched, installed or uploaded. Observations describe shipped artifacts and client request construction, not tested server responses. This report supplies evidence for the separate Topic 3b code comparison; it does not perform that comparison or change OpenStream.

## Comparison / summary

| Area | Evidence-backed lesson | Boundary |

## Findings with evidence

### Folder-to-item scanning and metadata — partly answered

1. **Separate the legacy readable rules from the current native scanner.** `S/Series/Plex TV Series.py` is a one-line native-scanner stub. Scanner strings identify `NativeMovieScanner` at `0x43ba68` and `NativeSeriesScanner` at `0x43bf15`, with local metadata, agent matching, database and analysis stages nearby (`0x43ba7e–0x43bc0d`, `0x43bf2c–0x43c0f8`). Those stage names do not prove exact sequencing. The following Python rules are shipped reference implementations; their presence does not prove current native defaults.
2. **TV parsing handles strong identifiers before weaker guesses.** `S/Series/Plex Series Scanner.py:8–19` defines season/episode, episode range, `3x03`, specials, weak numeric and date patterns. Lines 48–79 use stronger patterns at the top level and map one multi-episode file to separate episode items with divided display offsets. Lines 91–132 derive identity from episode/show/season folders; 143–206 examine MP4 tags and filename information. Lines 211–235 distinguish air-date episodes and explicit season/episode matches. Lines 246–291 remove misleading technical numbers and guard weak matches against movie-like folders, specials and absolute-order ambiguity. Lines 314–343 provide episode-only fallback and control stacking. SHA-256: `c2ac2b398957c6f11a0dec1c268ef8617524e5e42bd5c20307753838136d08c6`.
3. **Movies and multipart are not just a filename regex.** `S/Movies/Plex Movie Scanner.py:17–71` handles DVD/BD directory structures; 76–107 cleans filename title/year, rejects strong TV identifiers and can use a single-movie folder's name; 109–134 assembles numbered CD subfolders. `S/Common/Stack.py:11–68` groups part/disc-like adjacent names, appends parts to one item and explicitly excludes volume-like sequel names. Scanner SHA: `07ccd084afb4e57ef875d393661479a33011bd4b144f8459ea549cc0344c3c0d`; Stack SHA: `e5996fc460ea4645d31836a382d504d6da1cad8a37e5467775dca0e5f648d03a`.
4. **Filtering prevents false library items.** `S/Common/VideoFiles.py:5–14,198–238` filters extensions, extras/trailers/samples and selected directories; the sample size guard is 300 MB. Lines 38–185 normalize Unicode, delimit year detection and clean release/technical tags while protecting short titles. `S/Common/Filter.py:7–48` implements `.plexignore` filename/relative-directory patterns at root/current-folder scope; 65–85 rejects hidden, broken, zero-length or unreadable files. VideoFiles SHA: `731410b35c61da3470211870da8dd2727c581ce563bec78b9a223d16684883d9`. These are useful fixture categories, not rules to copy into OpenStream.
5. **Metadata matching is a ranked/fallback operation in the bundled agent.** `P/Resources/Plug-ins-e5521bd8c/PlexMovie.bundle/Contents/Code/__init__.py:15–22,163–197,344–463` defines confidence values, title/year/percentage/count penalties and candidate sorting/deduplication. Explicit IDs can resolve at score 100 (361–381); scores at least 98 can stop additional nonmanual search (425,451); TMDB is a fallback (455–459). SHA: `79de564031ebffa11b553556ef615c7e091ed9247e0aa845d5d0748d3d63ffb2`. These numbers belong to this legacy agent, **not a verified current native matcher or universal confidence scale**. Native cloud-agent score/override behavior was not recovered.
6. **Rescans have multiple triggers and scopes.** PMS settings at `0x122f8ca–0x122fa6b` describe automatic folder-change scans, partial scans limited to the changed folder and periodic scans with interval options from 15 minutes to daily. FSEvent-related setting keys occur at `0x10991d0/0x10991f0`; imported FSEventStream names corroborate platform notifications. Empty-trash-after-scan is a separate setting at `0x122fab6`. Defaults, debouncing, cancellation and exact deletion rules are unknown. `M:275510,277686` constructs individual item `/analyze` and `/refresh` operations; a whole-section refresh endpoint was not firmly recovered in this pass.

### Watched, Continue Watching and Up Next — partly answered

7. **Position and watched state are separate.** `M:195599` represents `viewOffset`, `viewCount`, `duration` and `lastViewedAt`; `M:301159` resumes from the offset unless a start override exists. The local manual-played update at `M:279832` clears offset and sets view count to 1 or 0. It is an optimistic client update, not proof of every server transition.
8. **Completion is configurable and can use credits.** PMS `0x122fdb9–0x122ff86` describes a progress-percentage threshold plus completion modes using selected percentage, final credits, first credits or the earliest of percentage/first credits. The explanatory resource says percentage applies when markers are absent. **The numeric default was not established; no 90% rule is asserted.** Continue Watching has configurable week window, maximum item count and inclusion of season premieres (`0x122fb3f–0x122fc97`); corresponding keys include `OnDeckLimit`, `OnDeckWindow`, `OnDeckIncludePremieres` (`0x100bf18`, `0x100bfc0`, `0x10a78a0`).
9. **The client delegates ongoing eligibility to the server.** `M:440482` requests `/hubs?identifier=home.continue,home.ondeck`. Starting a show/season requests `includeOnDeck=1` at `M:284383`, selects the supplied On Deck item where appropriate, otherwise chooses an unwatched season child or first child, and uses continuous playback for show/season/episode contexts. Remove-from-Continue-Watching at `M:3099716` resolves the server-advertised `RemoveFromContinueWatching` action and PUTs its returned key with `ratingKey`; this is a dynamic action, not a hardcoded endpoint. Complete entry/exit, rewatch, specials and ordering predicates remain unresolved.

### Hubs and home ordering — partly answered

10. **Rows are requested and managed through hub APIs.** `M:180388` builds `/hubs` or `/hubs/sections/{id}` requests with count/hubCount and inclusion options; nearby code can remove empty eligible rows. `M:1987792` references `/hubs/sections/{id}/manage`; `M:3019477` maps Continue Watching, On Deck and recently added categories. These support server-supplied rows and managed section hubs; they do not establish one order across users, server versions and libraries.
11. **PMS contains richer eligibility templates.** At `0x11733fa–0x11737e5` are recent additions, popularity, recently released movies, unwatched recommendations, actor/director/genre rows, recently watched items, collections and playlists. Recently released includes a last-year/release-date-descending template (`0x1173623–0x117365e`). TV templates (`0x1174445–0x11745d1`) include recently released episodes, newly added episodes, start-watching, rediscover and top-rated. Start-watching's template uses `viewedOrInProgressLeafCount=0`; recently watched uses last-viewed descending with watched/no-offset conditions (`0x1173738`). Hub-cache event/invalidation diagnostics exist at `0x1174714/0x1174762`. Template presence is not proof of default row visibility or merge order.

### Intro, credits and commercials — partly answered

12. **Fingerprinter computes audio fingerprints, not final intro boundaries by itself.** REA opened `/tmp/openstream-worker-b-fingerprinter-arm64` (SHA `8324dad295bb72ba2dec77739e22099e21bf1f8e674de689b6c40f8ba50b3ca6`). Search Evidence `ev_b5643c00747275618468be4092b251b88ae86c94e816ffab50e93231bd55b68b` located `FINGERPRINT=` at **VA** `0x10000b0e0`; xref Evidence `ev_54e4d5289d5e3c27c00a42ca2fdb07032f281b4089f0fad92fdc856c00e747a3` points to VA `0x100003eb0`. Containing-function Evidence `ev_4f5f621a198af66df4cd3b2b647d3813846ca9e79be15c34cf4c53ff3e3810c8` and pseudocode `ev_2be31176533efac71afb0de78a56dc3b55568f8acc7952698859a0197c152902` recover `FUN_100003828`. It obtains Chromaprint fingerprint size/data, handles empty/error results, selects raw/compressed output and formats plain/JSON or duration/fingerprint text. Decompiler warnings include unreachable blocks/type propagation; no similarity matcher was recovered. Help strings describe audio input, length, overlap/chunk and timestamp options. No tool was executed on media.
13. **Intro orchestration is a separate season-level candidate.** PMS `0x11a8eef–0x11a91de` contains intro-job diagnostics, FLAC/fingerprinter/raw/length arguments, missing/disabled/up-to-date guards and a diagnostic about clearing data when fewer than half of episodes qualify. Scheduled intro processing is represented at `0x1167715`; `GenerateIntroMarkerBehavior` at `0xfe5a40`. Together these support audio-fingerprint processing of episode groups. They do not establish the comparison window, similarity threshold, exact half-episode predicate or final marker algorithm. OpenStream intro fingerprinting remains tabled.
14. **Credits have distinct state/model/online-marker plumbing.** PMS `0x117e88f–0x117eca6` represents status, timestamps/indices, version/error, disabled/missing/multipart/media-change guards, online matching, retries and final-credit marker fields. Scanner strings reference `model_v1.pb` (`0x4363d0`), a detect-credits operation (`0x483f4a–0x483f5b`) and `/library/metadata/%d/credits` (`0x4861f0`). Scheduled credits processing is represented at PMS `0x11673d8`. Model presence plus diagnostics suggests a model-based path, but model inputs, feature extraction, thresholds, downloaded-model integrity and when online/local results win were not recovered.
15. **Commercial detection uses Comskip-style evidence and EDL exchange.** Commercial Skipper's config text at `0x3a3d0` describes weighted evidence including black/uniform frames, logo, scene changes, resolution, captions, aspect and silence; `comskip.ini` is named at `0x3bb3b`. PMS `0x117857e–0x11786aa` identifies `.edl`, the skipper, configuration/output/verbosity arguments, EDL completion, timeout and parse diagnostics. Per-part scheduling and disabled-library/marker diagnostics occur at `0x11787af–0x1178864`. This supports a media-part-to-EDL-to-marker pipeline; exact scores, selected settings, recording-only eligibility and post-recording versus background scheduling are unknown. XML commercial-boundary strings in the tool are alternative format inventory, not proof PMS consumes XML.

### Playback decision and play queues — partly answered

16. **The client contributes capabilities and explicit stream choices.** `M:490994–499000` builds profile allowances and checks force/allow-direct-play, protocol/container/MIME, browser codec support, selected audio and profile bounds. `M:531694–532232` sends playback/transcode session IDs, protocol, directPlay, directStream, directStreamAudio, offset, context/offline state, subtitle mode and `X-Plex-Client-Profile-Extra`. Universal URL construction at `M:557000–558700` includes media path/index/part, protocol, seek, subtitles/audio options, LAN/WAN location and request headers. Desktop uses a named profile at `M:3075988`. This is more than checking a container extension.
17. **Server decision supplements local estimates.** `M:533800–535000` requests the decision variant of the playback URL for eligible content, with approximately 2-second ordinary/20-second offline timeouts, then parses general/MDE/transcode decision codes/text and ABR information. Its network-failure path retains a local decision. Decision metrics distinguish video/audio/subtitle (`M:1209552`); the session model records separate video/audio decisions and hardware decode/encode fields (`M:188847`). Direct play sends original media; direct stream/remux can preserve eligible streams while audio or subtitles require conversion; video transcoding is another decision. Server bandwidth policy, hardware-selection logic and actual behavior were not decompiled/tested. Universal ping/restart handling is at `M:381903`.
18. **Queues are server objects with version and window state.** `M:283700` uses POST for a new queue and PUT for an existing one, supplying URI/playlist/key/type, shuffle, next and continuous context. Fetch at `M:305524` includes chapters/markers/repeat and resolves pending/error state. The model at `M:705606–706950` carries queue ID/version, item IDs, selected offset, total size and an available range; a queue may be a partial window rather than the whole list. Move operations use `/playQueues/{id}/items/{itemId}/move` with `after`. The inspected client also distinguishes current/upcoming ranges. Complete autoplay timings/end-of-part/repeat behavior are documented in the earlier skip/next report, not re-established here.

### Live TV and DVR — high-level, partly answered

19. **Tuner and EPG responsibilities differ.** Tuner Service contains native channel-scanner and EIT/DVB EPG identifiers at `0x18b2fc`, `0x186ac8`, `0x18cb70/0x18cb8c`. PMS has XMLTV read/download/parse diagnostics at `0x11f441c–0x11f4a89`; the client recognizes the XMLTV provider at `M:438650` and builds file-based lineup identifiers at `M:1971555`. These support broadcast-guide and XMLTV input candidates, not a universal EPG source or configured user's lineup.
20. **Discovery, mapping, tuning and recording are separate contracts.** `M:3150314` discovers grabber devices; `M:719288,719742` lists devices/DVRs. `M:3160934–3162855` requests channel maps, lineups, countries, regions and languages; related code searches lineups by country/postal code. Tune at `M:335884` POSTs to `/livetv/dvrs/{id}/channels/{channel}/tune` with session/timeout and requires a returned grab operation. `/media/subscriptions` models recording rules, target library/location and parameters (`M:264615`); `/template` and `/scheduled` are used (`M:266042,257344`). `M:2692696` uses new-only/all-airings choices. DVR guide reload and DVR/device preference updates occur at `M:818119–819884`. `D:55376,60228,66318` uses start/end padding offsets in seconds, converts them to display minutes and adjusts scheduled recording bounds. Conflict priority, padding defaults, retention, series matching and tuner-sharing policy were not recovered.

## Not found

- Current native parsing/matching precedence and score thresholds; bundled Python behavior is not current-native proof. Whole-section rescan endpoint, notification debounce, scan transaction boundaries and missing-file deletion defaults.
- Numeric watched default; complete Continue Watching/On Deck inclusion, expiry, suppression, rewatch and special-episode predicates; stable home-row ordering across configurations.
- Intro similarity/window algorithm, exact execution policy and final boundary selection; credits model inputs/thresholds; commercial scoring defaults, exact recording eligibility and complete scheduling rules.
- Full server transcode policy, hardware selection, observed direct-play/remux/transcode behavior or latency; complete queue/autoplay transitions beyond the inspected paths.
- Configured EPG source, DVR conflicts/priorities/retention/padding defaults, tuner-sharing behavior and real tune performance.
- Persistence/schema migrations, offline-source retention and synchronization/backup policies were not established in this topic. Topic 3b should keep these gaps explicit.

## What OpenStream should do

1. Keep source discovery, file enumeration, item identity, metadata matching and media analysis as distinct operations with independent retry state.
2. Build owned parsing fixtures for strong/weak episode patterns, air dates, season folders, Unicode, technical numbers, multipart and extras. Preserve the original path and record parsing confidence without copying Plex rules.
3. Preserve explicit provider IDs and manual matches through rescans; use ranked title/year candidates and a visible correction path for ambiguous matches.
4. Store resume offset independently of completion and last-viewed state. Define/test our completion policy and marker fallback instead of assuming a Plex percentage default.
5. Give Continue Watching and Up Next explicit eligibility/expiry/suppression policies; respect server-provided state for server sources and preserve a clear local policy for SMB.
6. Let home rows derive from index/state, support empty-row removal and stable ordering, and invalidate only affected rows when progress or catalog data changes.
7. Keep chapter/intro/credits/commercial markers typed with provenance, media version and final-credit flag. Use approved chapters first; this report does not reopen tabled intro fingerprinting.
8. Model video, audio and subtitle decisions separately. Compare AetherEngine/device/route capabilities before choosing original media, remux or conversion; show the selected path in diagnostics.
9. Make playback preparation bounded and recoverable. A server decision timeout needs an explicit fallback/error policy and must not silently make an unsupported stream playable.
10. Give queues stable identity/version and item identity; distinguish the total queue from a loaded window and test next/reorder/repeat across multipart boundaries.
11. Separate IPTV channel identity, EPG lineup mapping, live tuning and recording rules. Preserve source IDs, timestamps/time zones and guide reload state; define padding/conflict/retention policies before adding DVR.
12. In Topic 3b, compare each evidenced behavior with OpenStream path:line, then rank gaps. Treat stale/offline index retention and backup/sync as independent requirements because this investigation did not establish Plex's policies.
