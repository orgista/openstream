# Netflix GUI

Worker A, 2026-10-11. Static analysis of Netflix Android phone **9.87.1 build 9 74620**, with English and xxhdpi splits, plus a bounded Android TV inspection. No APK was installed or executed. **Observed** means shipped resources or recovered instructions, never a runtime screenshot. **Inference** is labelled. **Not found** means this pass did not establish the answer, not that the feature is absent.

## Findings with evidence locations

### 1. Home structure, row order and lazy loading

- **Observed controller:** `com.netflix.mediaclient.ui.home.impl.HomeEpoxyController` builds row containers from the supplied state's row list; `buildRow`, `addModelsForNotLoadedRow`, `addInitialLoadingShimmer` and `errorLoadingLolomo` are distinct paths. Supplemental `HomeEpoxyController.java` lines 1011–1125 iterate `state.getRows()`, handle unloaded rows and build available rows. Lines 1285–1286 add a loading creator when loaded items are fewer than `LoMo.getLength()`. This establishes partial row population and placeholder handling, not a measured network prefetch distance. Class evidence: `ev_fd077a33be391cfa8d573ff5b91bffd632e0a42036d4027ec11dbe458fbb1535`.
- **Observed row vocabulary:** `LoMoType` includes billboard, Continue Watching, instant queue, Top Ten, content preview, downloads for you, trending now, coming soon, reminders, trailers, my profiles, my downloads, notifications, favorite titles, recently watched and episodic rows. These are supported model types, **not proof they all appear for a given profile**. No fixed Home row order was recovered: the controller follows supplied row order.
- **Observed list hierarchy:** row models use a horizontal RecyclerView/Epoxy arrangement inside the outer feed. `HomeEpoxyController.getRowLayoutId()` selects layout `0x7f0e0186`, whose decoded root is `o.kui`, match-parent width, wrap-content height and `clipChildren=false`. Evidence: `ev_eca78651ab5927b70c5a7fdcda3af895b899f1e4569127bd2a4e9890117586db`. This is a recycled/lazy architecture; actual memory use and scroll smoothness were not measured.
- **Observed billboard:** `LolomoEpoxyController.buildConfig` assigns the billboard a one-item-per-page configuration via `o.kRv.b.d()`, separate from ordinary posters, Continue Watching and Top Ten. A billboard view also has preview-controller dependencies; the presence of those dependencies does not establish an autoplay policy. Evidence: `ev_81b09c028fd58db10cfe41bac2b01048d778a86141381673c82452c50afc129e`.

### 2. Card sizes, spacing, styles and titles

- **Observed ordinary configuration:** `o.kRv.b.b(Context,int)`, overload 1, supplies aspect scalar **0.71**, item-padding resource `0x7f0702fe` (**4 dp**), horizontal-list-padding `0x7f0702ff` (**8 dp**), peek ratio **0.25**, and free scrolling. Evidence: `ev_0dd46b89abba71e4fef28ee391cc8f53373e00dcf3ef9818fbac20c4ba504137`. These are configuration fields: a 4 dp padding field is not a runtime measurement of the entire gap between two cards.
- **Observed responsive page count:** REA `kotlin.kRA.c(Context)` reads orientation and Android `screenLayout` size; `kotlin.kRA.b(int,int)` returns portrait small **2**, normal **3**, large/xlarge **4**; landscape small **3**, normal/large **5**, xlarge **6**, with an unknown-size fallback of **2**. Evidence: `ev_e5a722649e64e53bd9c6fb265fed86c8a3baa2db662236fcaf2fbb3ceae748b2`, `ev_155a53e9741edd5d2538dff99c81a0284d8a792bcc7dd7212fed2bf95e6c9978`. These are **items per page**, not the total number of items in a row. Width depends on the viewport and configuration; no universal fixed poster width/height in dp was established.
- **Observed ordinary poster model:** supplemental `o/C26321lad.java` selects standard/Top Ten card models; `C25342kvS` → `AbstractC25334kvK.e()` selects layout **0x7f0e00e7**. Its single `o.gKK` image uses `centerCrop`, adjusted bounds and style **0x7f15060b**; there is no separate visible under-poster title TextView in this model. `res/values/styles.xml` lines 3530–3533 map the style to rounded-corner resource **0x7f0702da = 4 dp**. Accessibility/title data elsewhere is not evidence of a visible label. Some other row types may have text or differently composed artwork.
- **Observed variants:** Continue Watching has a different row config (type 2), with aspect scalars **0.5128205** and **0.58823526** selected by a device helper; the exact helper-to-device interpretation was not established. Top Ten uses type 11, aspect **0.71**, zero item/list padding in its config and **0.25** peek, with separate rank decoration. Supplemental replay location: `LolomoEpoxyController.buildConfig` and `o.kRv.b` methods. Do not transfer these values unchanged to iPhone.

### 3. Top 10 numeral treatment

- **Observed setup:** REA `kotlin.kRy.c` creates `dRq` with **60 dp** from dimen **0x7f070818**, bottom positioning and a **0.5** sizing factor. Evidence: `ev_ada20611553d0b6f2bca848f54fc1ee8dab05190bd40ea9ad28746e492767220`. Supplemental CLI alias is `o/C23982kRy.java`.
- **Observed drawing:** `kotlin.dRq.onDraw` uses **adapter position + 1** as the rank, computes decorated card bounds, mirrors for RTL and handles the next partially visible position. `dRq.a` sizes the numeral to half the card height; item offsets reserve space for the rank, and its baseline is bottom-relative with an 8 dp adjustment. Exact runtime overlap and treatment of ranks beyond the supplied Top Ten data were not measured.

### 4. Continue Watching: progress, controls and removal

- **Observed card layout:** REA `kotlin.kXL` is the Continue Watching view. Its constructor inflates **0x7f0e0062**: artwork, then progress view **0x7f0b01cc**, then a play/menu information strip. In this resource the progress is **below the artwork**, not overlaid on it. Default dimensions **0x7f0700e4–0x7f0700ea** include **40 dp** strip height, **2 dp** drawn progress stroke, **4 dp** progress-view height, **6 dp** progress padding and **2 dp** bottom margin; `sw600dp` changes strip height to **32 dp** and bottom margin to **4 dp**. Play/menu views are separate targets; the strip has a divider. There is no separate visible title text in this layout.
- **Observed progress binding:** `kotlin.kXL.e`, overload 1, reads progress through an offline/profile-aware helper, assigns the custom drawable's fraction and invalidates the view; it separately requests artwork and binds accessibility/title data. Evidence: `ev_bfb04fa5656f13278dfcfe4f63802088041d238918aa27ab56594080fa4ce91c`; supplemental `o/kXL.java` and nested drawable `kXL.a`. This establishes progress rendering, not Netflix's threshold for putting/removing a title in the row.
- **Observed menu construction:** `com.netflix.mediaclient.ui.home.impl.lolomo.cwmenu.ContinueWatchingMenuController.addItems` adds a clickable title-header model, details action (show versus movie label), eligible download action, rating actions conditioned on the current rating, then remove-from-row. Download branches distinguish an episode, a next episode and a movie. String IDs are **0x7f14071d/0x7f1406e5** for details variants, **0x7f14035b/0x7f14035e/0x7f14018d** for download variants and **0x7f140d4b** for removal; these are evidence locations, not proposed OpenStream copy. Evidence: `ev_ae0196ee668d8ced2eef762d240f4ad1184d41bc5ed069406d40491736260e48`.
- **Observed confirmation:** `onRemoveFromRowClicked` presents an OK/Cancel confirmation using string **0x7f140259**, then routes through callbacks/session logging and a remove/refresh event producer. Evidence: `ev_89d8a5bf2d80430887f69cd2789d6f61465216ae1fedb3713eba9982f1c5f3d9`; supplemental controller lines 466–489 and 697–712. The end-to-end persistence transaction, failure restoration, undo and cross-device propagation were not established. Removal must not be equated with deleting downloaded media or marking the title watched.

## What OpenStream should do

1. Use a billboard followed by lazy horizontal shelves with stable row/item identities. Keep ordering a deliberate OpenStream policy rather than assuming Netflix's server-selected sequence is fixed.
2. Tune portrait poster density from available width with tight spacing and a partial next-card cue. Treat the recovered 0.71 aspect and 4/8 dp padding fields as comparison inputs; verify our Apple layout independently.
3. Keep the owner-approved titles under posters and Continue Watching progress **on artwork**, even though these recovered Android models differ. Give each card a readable accessibility title, progress and resume action.
4. Give Continue Watching an overflow with details and remove, plus download only when supported. Make remove affect that profile's row state independently of watched state or deleting an offline file; choose confirmation or undo explicitly.
5. Render Top 10 numerals with our own system typography, outline/fill and RTL-aware geometry; announce rank in accessibility rather than exposing duplicate numeral text as a separate control.
6. Make detail Play the clear primary action, download capability-dependent and automatic per owner policy, and save/list secondary. Let unavailable/offline states determine enabled actions instead of rendering inert buttons.
7. Show a season selector only for multiple seasons; preserve selection and scroll identity when episode pages load. Give episode rows number/title, runtime, synopsis, progress and meaningful download status.
8. Expose profile and downloaded items through OpenStream's existing system navigation. Use the system tab bar, accent **#FF3366**, automatic downloads and no source picker; do not import Netflix's experimental tabs or custom tab paint.
9. Render content that is ready while other rows load. Use appropriately sized placeholders and retry at the failed row/section; distinguish an empty saved list from failure without adding explainer prose to normal screens.
10. Keep any approved billboard motion bounded, stop work offscreen and honor reduced motion. Trailers remain tabled; a recovered preview dependency is not a reason to add autoplay. Use only the owner-approved billboard fade, without additional scrims or gradients.

## How this was done

- Read all Apple agent instructions, the assignment, the existing reference report and `reverse-engineer-anything` skill/Android reference; checked the live usage board before heavy work. Used REA MCP package/resource/class/method tools against existing artifacts on Dev-Mini over its configured SSH server.

No assets were imported.
- Used existing apktool **3.0.3**, ripgrep and JADX CLI on Dev-Mini to follow numeric resource IDs and obfuscated aliases in `/tmp`. CLI `jadx -j 1 --no-res --decompilation-mode simple` finished with **225 decompilation errors**, exit 3; usable files were inspected individually. Simple mode has labelled/goto and occasional unknown-type output, so uncertain branches were not promoted into precise behavior.
- REA `buildModels2` selectors on Home/FullDp returned **body_status=not_available**; this is a provider/alias limitation, not proof the app lacks those methods. Supplemental controller bodies supplied bounded evidence. Alias differences required class inventory/CLI matching. An initial supplemental lookup used the wrong ContinueWatchingMenuController directory, returned `No such file or directory`, and was corrected with `rg --files` to `impl/lolomo/cwmenu/`.
- No installs, execution, account access, DRM bypass, native sessions, uploads, builds, tests, simulators or emulators. Only this report and the assigned Paramount report were written in the repository; scratch stayed on the mini in `/tmp`. Findings inform independently written OpenStream behavior, not copied implementation or assets.
