# Apple TV heroes and main GUI: polish comparison

Worker A, 2026-10-11. **Static shipped-artifact inspection, not a runtime visual audit.**

## Summary

Apple's installed Mac TV app exposes a template-driven media showcase, context-specific lockups, platform-specific artwork/crop fields, independent metadata transitions, configurable paging, and accessibility-aware presentation. It does **not** expose a local Home storyboard or a self-contained JSON template with the active hero dimensions and timings. This pass therefore establishes the vocabulary and resource support, not a measured Apple TV screen or universal configuration.

OpenStream already has the important structure: a billboard, a separately loaded wordmark, capability-dependent primary action, lazy shelves, focus-aware paging and a timer held offscreen. Preserve that structure. The strongest actionable findings are our tvOS poster-caption suppression, the extra bright-art leading fade relative to the assignment's single-fade constraint, and the timer continuing while a requested page waits for artwork. Geometry, timing, blur and parallax changes should follow a later authorized visual comparison rather than invented Apple constants. Twelve ranked proposals appear below; evidence strength and unresolved behavior are explicit.

**Platform boundary:** this artifact is the **Mac** TV app and its Mac system frameworks. Shared keys include phone, iPad and TV artwork variants, but that is not an inspection of the tvOS binary. Mac hover/sidebar behavior, Mac point sizes and library nib frames must not be transferred to Siri Remote focus or a 1920×1080 tvOS stage. No reference code, strings, art, icons or assets were imported into OpenStream.

### 3. Hero paging, transitions, focus and scrolling

**Observed configuration keys:** VideosUI's showcase area contains `autoAdvanceToNextPageEnabled` (`0x2A27D2A06`), `advanceToNextPageDelayDuration` (`0x2A27D2A25`) and a separate `advanceToNextPageDelayDurationImageOnly` (`0x2A27D2A4D`). It also contains `autoSwipeAnimationDuration` (`0x2A27D2995`), `swipingEndAnimationDuration` (`0x2A27D297A`), `metadataFadeOutSpeed` (`0x2A27D2A99`), `metadataFadeInSpeed` (`0x2A27D2AAD`), `titleViewTransitionDistance` (`0x2A27D29C9`), `navigationBarTransitionDistance` (`0x2A27D29E9`), `itemHoverDelayDuration` (`0x2A27D2ADF`) and `hidePageIndicatorsDelayDuration` (`0x2A27D2B32`). A preloading field is `preloadImageBatchSize` (`0x2A27D2B48`); another configuration area includes `videoViewOffscreenThresholdToStopPlayback` (`0x2A27D2CBA`).

**Inference:** Apple accommodates different image/video dwell and independent art/metadata/navigation motion. **Not established:** whether auto-advance is enabled in this account/view, any numeric delay, whether paging slides or crossfades here, indicator shape/position, focus pausing, remote commands, or scroll-collapse thresholds. `parallaxEnabled`, `parallaxRatio`, `mirrorSlideParallaxRatio` (`0x2A27D2A5D`–`0x2A27D2A84`) establish configurable support, not observed parallax.

**Ours:** `AppleHeroRotation.swift:13` is **12 seconds**, maximum five candidates (`:17`). This is an OpenStream choice. Discover uses the stateful TV carousel, not simply the clock-derived `index(at:)`: `AppleDiscoverView.swift:207` routes through the Home carousel; `AppleHomeTVHeroCarousel.swift:84` holds rotation while focused or invisible. Left/right paging stops and Play focus entry are already implemented (`:50`, `:121`). The indicator has a 4-point height, 14-point inactive and 48-point active segment (`AppleTVBillboardMetrics.swift:64`), with a .3-second snappy index animation (`AppleHomeTVHeroCarousel.swift:242`). Apple parity for those numbers is unresolved.

`AppleHeroPageGate.swift:25` holds the displayed page until requested art/wordmark settle, while explicitly leaving the rotation clock untouched. `AppleHomeTVHeroCarousel.swift:75` advances using the requested cycle's due date; a slow image can therefore consume part of the requested page's dwell before it appears. This is a **source-derived risk**, not a reproduced failure or an established Apple behavior. The gate changes shown identity (`AppleHeroPageGate.swift:92`) without a local explicit page animation. It already keeps art and copy together; preserve that property when considering transition polish.

Scrolling uses a normal vertical `ScrollView` (`AppleDiscoverView.swift:198`), negative hero bottom padding (`AppleTVBillboardView.swift:112`) and an offscreen visibility pause. No scroll-dependent title/metadata collapse is established in the inspected billboard view. Apple's distance keys alone do not prove a scroll-driven collapse either.

**Ours:** lazy rails use a 24-point tvOS card gap and 20-point vertical focus bleed (`AppleMediaShelf.swift:52`, `:104`; `AppleTVBillboardMetrics.swift:77`). **Observed Apple style fields:** `translateOffsetOnFocused` (`0x2A27EB158`), `contentMotionTranslation` (`0x2A27EB178`), `focusSizeIncrease` (`0x2A27EB611`), `focusCornerRadius` (`0x2A27EB5F1`), `animatesShadowChanges` (`0x2A27EB6F5`), `focusMargin` (`0x2A27EB891`), `backgroundMaterial` (`0x2A27EB6B2`), `vibrantMaterial` (`0x2A27EB82F`), `reduceTransparencyBackgroundColor` (`0x2A27EB2D1`), `highContrastBorderColor` (`0x2A27EB2F7`), `numberOfLinesAXLarge` (`0x2A27EB494`) and `languageAwareSystemSpacingMultiplier` (`0x2A27E14A4`). These are generic style capability evidence; no particular hero/card's scale, shadow, blur recipe, duration or curve is proved.

**Observed bundled styles:** REA TextStyles Evidence `ev_35af5842e9030dfbc2f2f0d6b251a535f1af8aaa39804e9fb6e1e1f1f53e040a`. TV's `TextStyles.plist` includes style IDs 10001/10002 (34 regular/bold header), 10003/10004 (24 regular/semibold title), and 10310 (13 body), 10314 (11 subhead), 10318 (9 caption), using system/Helvetica system aliases. The same plist contains extensive legacy music/library styles. No recovered binding ties those IDs to the modern Home hero; **do not use them as tvOS font specifications**.

REA TV asset Evidence `ev_6512e23cc4f0d6a2dc1610c324b93b6233f31b1c76187f5634d662a551d4cfd1` inventories **7,865 records** (first 30 paged); catalog SHA-256 `a93ddff85b76d20b70b1bf16bb2a494e52c605088e9919d4b9f230ab393fad2a`. Its `KeyColor` is system blue. That is a bundle color, not evidence every Home label is blue. Keep OpenStream's neutral UI and owner accent #FF3366.

**Ours:** native borderless artwork highlight is already used (`AppleDiscoverView.swift:2105`, `:2143`). Hero round controls scale to **1.06**, shadow radius 14/y6, ease-out **.16 seconds**, with Reduce Motion suppression (`AppleHomeTVHeroCarousel.swift:194`). Apple reference values remain unknown. Our header uses 38 bold; page chrome uses 48 bold/80-point inset (`AppleTVChrome.swift:14`), neither recovered Apple constants.

The inspected billboard invokes `AppleHeroScrimView` (`AppleTVBillboardView.swift:70`); for bright art `AppleHeroScrim.swift:119` adds a leading fade as well as a stronger bottom fade. The assignment allows only the approved billboard fade and no extra scrims. Treat this as a review of an existing owner-rule discrepancy, not authorization to add more material/gradient effects. Apple's `gradientUsesImageColor` (`0x2A27D2AF6`) and generic gradient classes do not override that constraint.

### 6. Empty/loading support and safe failure

**Observed:** VideosUI assets metadata has **990 records**. `Generic16x9Placeholder` is **534×300 pixels at scale 1**, `GenericPlaceholder` 1×1, and `MonogramPlaceholder` 300×300. `resource://Generic16x9Placeholder` occurs at `0x2A27DB911`, linking a named resource reference to the catalog. Pixel dimensions are intrinsic asset dimensions, not rendered card dimensions. Supplemental `assetutil --info` retained metadata only, no image extraction.

Localization above distinguishes library loading, offline, no connection, empty library and fetch-error categories. Strings at `0x2A27E48A0` / `0x2A27E48F5` describe retrying collection/template requests on a later trigger, but do not prove retry cadence or the Home failure UI. `collectionIsPlaceholder` (`0x2A27E1AD7`) establishes a collection placeholder field.

**Ours:** first-load Discover is a full-page spinner until content exists (`AppleDiscoverView.swift:177`); once content exists it draws the available rails. Cards have a named text placeholder (`:2197`) and a very subtle default loading fill (`:2522`). Apple shimmer, loading delay, per-shelf retry UI and error-restoration semantics were not recovered. Report proposals below must not introduce normal-screen explainer prose.
