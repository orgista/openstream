## Findings with evidence locations

### 1. Screen layers, guide entry and focus

- **Observed resource structure:** `res/layout/fragment_livetv_video.xml` contains `video_frame`, `channelSelectorFrame`, `discoveryFrame`, `inScopeDetailsContainer`, `playerDetailsDrawer`, two independent startup/loading progress views and `errorToast`. The drawer is initially hidden. `res/navigation/livetv_nav_graph.xml` starts at `LiveTvVideoChannelsFragment` and accepts channel/listing/category identifiers, content-lock and parental-PIN arguments. This is an Android TV full-screen host; it does **not** independently verify the iPhone-style pinned-player arrangement in OpenStream's reference brief.
- **Observed guide implementation:** `LiveTvVideoChannelsFragment.Q()` reuses/shows an existing guide fragment or creates `defpackage.tz4` under `EPG_CONTAINER_TAG`, with fade-in/out animations. `K(boolean)` removes it and can reset a non-All category. `tz4.onCreateView()` creates a ComposeView. Evidence: `ev_d6a8c453114bba1fc3a195868dd2df66cfb1a397a0a89d163356096e00366977`, `ev_b610c68135558b612b33a2dae37a7a9751ae98732881f00e1b08d6e9c62cd4f9`; supplemental fragment lines 346–432.
- **Observed state model:** `defpackage.e05.toString()` names selected content/channel, currently watched listing, focused content/channel/listing position, categories, loading/initialization, details-drawer visibility, DMA item and explicit requests to focus the grid, categories or channel icon. Focus and selection are represented separately. This supports a distinct browse state; it alone does not prove that every focus move leaves playback untouched.
- **Observed directional affordances:** decoded `res/values/strings.xml` keys `compact_epg_category_action_hint` and `press_up_or_down_for_channels_press_right_for_channel_timelines` describe category-to-channel and channel-to-timeline moves. These are accessibility/help resources, **not a recovered complete focus graph**. `LiveTvVideoChannelsFragment.dispatchKeyEvent()` handles Back/gamepad-B (4/97): an open details state closes and requests frame focus, or an in-scope navigation host receives the event and pops its stack before the host closes. Evidence: `ev_b810b105e8c903661cbff0e22d1c24c80f39e61fcd2841579b8fc28b3567f443`.

### 2. Channel surfing, selection and tuning

- **Observed surf key path:** `defpackage.cl9.s(py1)` routes a particular player focus state to `ChannelChanger`. Enter (66), DPAD-center (23) and numpad-enter (160) toggle expansion on key-down; Enter ignores repeats. Back/B collapse an expanded control on key-up. Up/down (19/20) call its step handler; left/right key-down is consumed in that branch. Outside it, keys go to another skin dispatcher. Evidence: `ev_928c6a66d7909f031144c408d156ce3170c76d6407d33ef5779e3465efd52282`. This is state-specific, not a universal full-screen key map.
- **Observed input timing:** `defpackage.pqe.l(KeyEvent,d52)` consumes up/down down-events when the surf control is collapsed. When expanded, a short press invokes the step callback on release; held repeats invoke it with a **400 ms** throttle. A release also requests a **260 ms** control animation and, conditionally, schedules **3,000 ms** auto-hide. Evidence: `ev_75b0eb882471a0018763b25833df1617a40c2e2de4e14a85f5f2165f1cd21bff`. These are interaction timings, **not channel acquisition times**. `cdc` → `bdc` → `CbsPlayerViewGroup` → `w02.invoke`, case 20, forwards the step direction; the final step-to-stream transaction was not established.
- **Observed browse/action distinction:** `defpackage.u05.R0(sph)` changes selected-channel metadata/focus state, with a metadata-loading coroutine when the channel has no listing. Its larger `T0(tqh)` dispatches separate events and includes named `onWatchLive` and locked-content handlers. Evidence for R0: `ev_79cdf3661be3a7c4e998c12fdfe0541352d9230ad7e0d81796321bae32b57908`; supplemental `u05.java` lines 172–282 and 429–1024. **Inference:** the guide is intended to support browsing independently of an explicit watch action. Preview-on-focus versus tune-on-select across every guide/card path remains unverified.
- **Observed loading affordances:** the host layout has ordinary and deep-link startup spinners; the DVR skin has a central buffering spinner. `u0()` shows the startup loading view and hides its frame; `P()` hides another progress view. Exactly which old frame/thumbnail remains visible during a channel switch and how quickly the first new frame appears: **not found**.
- Number-key entry, channel +/- hardware keys, and a last-channel shortcut: **not found** in the inspected surf handler. Unresolved common skin dispatch (`dl9.i`) prevents extending this negative finding to the whole app.

### 3. Guide content, paging and program details

- **Observed listing data:** `com.paramount.android.pplus.data.shared.dto.ListingResponseDto` carries program start/end timestamps, separate stream start/end timestamps, formatted times, title/description, channel identity, season/episode identifiers, rating/genre, fallback content/image flags and VOD availability. Supplemental `defpackage.tj9.toString()`, lines 266–307, exposes the corresponding transformed listing fields. The separate program/stream boundaries matter for live-event restart; they are not interchangeable.
- **Observed now/next ingredients:** timestamps and current-listing state exist; `defpackage.kz4.i` constructs listing-card data with progress calculated by `dp4.n`, start-time formatting and future/current comparisons. `kz4.j` failed type inference in the CLI decompilation, so no complete row-placement algorithm is claimed.
- **Observed actions:** `defpackage.fie.o(mph)` maps watch-live, watch-channel, play-VOD, more-info, channel-favorite, program-watchlist, restart and sign-in actions to presentation models. Evidence: `ev_76f892619a8085e94f11356eb287e6f285955d5e7b0fdabff1a2390b7940cb60`. This establishes distinct action types, not their eligibility or the order of buttons for every listing. `rn9.invoke`, case 0, composes a **320 dp** details drawer with a more-info callback; `mg4` carries synopsis, season/episode, favorite and VOD state.
- **Observed configuration variability:** `defpackage.lz4.toString()` identifies compact metadata/guide, category support, side navigation, activated state, loading-bones UI, upcoming-day display, favorites API use, locked-content policy, failure placeholder and guide-recreation control. Evidence: `ev_bbdff514a7a2ffd96fbaf0b17aa384c42d0c49747819ec554c392f0b62a1ee08`. `x50.<clinit>` declares `livetv_schedule_page_size`, `livetv_epg_auto_hide_time` and `livetv_channel_resume_time`; `o2a` persists the schedule page size as `app_config_livetv_schedule_page_size` (line 444). The actual value, unit and pagination request were **not found**.
- **Observed geometry resources:** `res/values/dimens.xml` defines channel-logo background width **92 dp**, normal logo **40 × 40 dp**, compact logo **72 × 36 dp**, favorite mark **12 × 12 dp**, featured logo **50 × 50 dp** and row spacing **6 dp**. `kz4.a` references these dimensions. They are Android TV resource values, not measured Apple-layout recommendations.
- Exact initial visible time window, tick interval, how many hours/days ahead/back, pagination overlap, a dedicated now/next row and behavior on EPG gaps: **not found**. The upcoming-day flag does not prove a multi-day horizon.

### 4. Restart, pause/rewind and live edge

- **Observed DVR presentation:** `res/layout/tv_live_dvr_content_skin.xml` contains station logo, program title, live label/dot, current time, thumbnail strip, seek bar, play/pause indicators, restart, jump-to-live, favorite, program-watchlist and settings controls. Start Over/restart is therefore represented separately from returning to the edge. Resources alone do not prove all controls are enabled for all channels.
- **Observed capability boundary:** `defpackage.bii` checks a content capabilities list for `DVR` (line 692); `lt3` checks `ContentType.DVR` (line 923). The media model also distinguishes live/DVR/VOD. The resource strings describe restart availability for live NFL games; this is supporting presentation evidence, not a universal channel guarantee.
- **Observed engine operation:** `AbstractAviaPlayer.seekToLive()` invokes `_seek(-1L)`. Evidence: `ev_1b019d71603e7625d057dc0d57e704fcc41ed20bb63b827a40a99436c1e33e00`. `AviaPlayerInfo` carries `isLiveEdge`, content duration/position, buffering state and live offset. Supplemental `AviaDecor` lines 448–465 map an at-edge playing position to the end of its seek bar; its scrub path pauses while tracking and resumes on release, using seek-to-live for the sentinel position. This generic engine decor was **not proven to be the TV DVR skin's exact active UI path**.
- **Observed remote caution:** `LiveTvFullScreenActivity.q()` consumes media play/pause, play, pause, next/previous, rewind and fast-forward keys after debounce unless routed through other handling. Evidence: `ev_e4157b9141d77f7593ab051e9a4e927e945a1d604151806dd5e786ffbf53a118`. Do not infer pause/rewind is disabled: the app has other dispatchers and skin actions. `dl9` has 100 ms long-press requests, but `dl9.i` did not decompile usefully.
- DVR history/window duration, exact seek clamp, live-edge tolerance, restart-to-program-start versus stream-start choice, behavior across program rollover, and pause limits: **not found**. `LiveTvVideoChannelsFragment.X()` reads a **7,200-second playback timeout** fallback; that is a session timeout, **not a two-hour DVR window** (`ev_15202b68d82d8dab0e0a2fb6b77d49738791d8f56a9607f9149c1bfd04da9fda`).

### 5. Mini-guide, affiliates, favorites and failure states

- **Observed overlay support:** guide entry runs within the live host, and configuration explicitly distinguishes compact guide/metadata and auto-hide duration. Back has layered dismissal. Exact overlay entrance gesture, whether playback is resized, actual auto-hide default and all cross-layer focus moves: **not found**.
- **Observed location data:** `ChannelDto` contains postal code and DMA values; `defpackage.ek` carries affiliate station/name/URL/logo fields, and `qj` sets an `affiliateFeed` flag in tracking parameters (lines 417–420). `e05` retains a DMA item. Location-restriction and out-of-market error resources are shipped. **Not established:** whether this build resolves affiliates using IP, device location, account address, a user picker or precedence between them; tracking metadata is not location-selection logic.
- **Observed favorites separation:** favorite-channel icons and selected/solid variants exist. `fie.o` and `mg4` distinguish channel favorites from program watchlist. `lzh` represents updated favorite channels/categories; `cc` names an open-guide/play-first-favorite event. The state model remembers selected/focused channels. API persistence, sorting, limits, cross-profile scope and a dedicated recents UI: **not found**; focus memory is not recents history.
- **Observed ads:** the DVR seek bar declares ad-pod markers while ignoring pre/post-roll pods in that presentation. `CbsPlayerViewGroup` exposes an ad container and ad-focus handling; `w02.invoke`, case 7, requests focus on an eligible ad web view. Generic Avia decor separately computes ad progress. This supports ad-specific player state, not an established live-ad countdown or blackout UI.
- **Observed errors:** `LiveTvVideoChannelsFragment.s0(String)` calls `t0(message,false)`. `t0` hides loading, resets player UI and installs `ErrorFragment` with `ERROR_MESSAGE`, `SHOW_BUTTON` and `SHOW_BACKGROUND`. Evidence: `ev_44bef620ddc053113d4edad0534580a3353dbcb3abe829b093a581c34964a632`, `ev_39ef97e942463ffa3667aeda8dc9bf611ef1cd3f8daf70960a95dfadaa6382f8`. Thus this path explicitly **does not show a button**; a retry label elsewhere cannot prove every channel failure offers retry. `oo9.invokeSuspend`, case 1, distinguishes DRM-license errors from a generic failure, delegates to the error handler and can dispose current media content. Other code composes an error toast (`rn9`, case 2). Automatic retry count/backoff, stale-response cancellation and blackout-to-error mapping: **not found**.

## What OpenStream should do

1. Keep the approved edge-to-edge pinned video, logo/now-playing channel list and secondary guide; this Android TV host is evidence for layer separation, not permission to change the approved layout (§1).
2. Maintain separate focused, selected and playing-channel identities. Browsing should update metadata; selecting should tune. Cancel stale tune results when another selection wins (§2).
3. Make tvOS Back close details, then guide/overlay, then leave Live; restore focus to the channel/control that opened each layer (§1).
4. Offer up/down surf in an explicit watching state with repeat throttling; test short press versus held input. Choose our delay through usability testing, rather than treating Paramount's 400 ms as a tune-speed target (§2).
5. Show channel identity and a clear loading state during tuning, with a recoverable error action. Measure selection-to-first-frame on our own engine/providers (§2, §5).
6. Read EPG program and stream boundaries separately. Display now/next and gaps honestly; page only within available provider data instead of inventing a guide horizon (§3).
7. Enable Start Over only for provider catch-up or retained live-buffer coverage; clamp pause/rewind to that actual range and preserve a separate jump-to-live action (§4).
8. Derive the Live indicator from distance to the playable edge; a playback timeout must never become a DVR-window constant (§4).
9. Keep favorite channels in My Channels and program watchlists separate. Preserve favorite IDs through lineup refresh without importing Paramount's account/affiliate policy (§5).
10. Distinguish temporary channel failure, access/location restriction and ended live event. Hide unavailable actions, offer retry where recoverable, and retain the guide for choosing another channel (§5).
