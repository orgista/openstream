# Infuse engine and local sources

Static REA deep dive, worker B, 2026-10-11. Target: Infuse 8.5.6 (8.5.5763), copied app on Dev-Mini. No target was launched, no account or share was contacted, and no encryption was bypassed. Observed below means observed in shipped artifacts, **not observed playback or UI interaction**. Proposals are OpenStream policy choices; no implementation, assets or UI strings were copied.

## Comparison / summary

| Area | Infuse evidence | Consequence for OpenStream |
|---|---|---|
| Engine | FFmpeg libraries, app-level VideoToolbox imports, custom audio/subtitle/rendering identifiers | AetherEngine's FFmpeg basis is a reasonable comparison point; codec availability alone does not establish output fidelity |
| HDR | Dolby Vision configuration, reshape metadata, HDR10+ probing, custom/system tone-map settings | Track detected format separately from selected output and device capability |
| Audio | Passthrough decoder/SPDIF muxer, Atmos eligibility selectors | Route and playback-rate guards matter; no blanket TrueHD Atmos claim is supported |
| Source setup | Protocol-specific strategies and fields; saved/discovered shares; connection-check/success resources | Save a connection, browse it, then choose library roots |
| Discovery | Bonjour service types, UPnP SSDP, Emby UDP broadcast identifiers | Discovery should complement manual entry; NetBIOS/WS-Discovery are unresolved |
| Library | Favorite-folder inclusion, library-mode/auto-scan settings, content/metadata/artwork stages | Index independently of browsing and expose concise progress/retry states |

## Findings with evidence

### Engine, libraries and versions — partly answered

1. **Bundled media stack.** `I/Frameworks` contains `libavcodec`, `libavformat`, `libavutil`, `libavfilter`, `libavdevice`, `libswresample`, `libswscale`, `libdav1d`, `libbluray`, `libudfread`, and `libnfs` frameworks. SMB uses `StratospherixLibSMB`; credentials have `UICKeyChainStore`. The main image directly imports FFmpeg packet/frame, demux, seek, decoder and subtitle functions, so this is stronger evidence than framework names alone. REA Mach-O Evidence above records their loads and imports.
2. **Upstream version versus app version.** Framework Info.plists uniformly stamp 8.5.6 / 8.5.5763; those are **not upstream library versions**. Embedded FFmpeg build strings identify `n8.0.1-14-gff95688e6f`: `libavcodec.framework/Versions/A/libavcodec` at `0xe02870`, `libavformat` at `0x1d0140`, and `libavfilter` at `0x39b7b0`. Codec and format strings identify Lavc 62.11.100 (`0xe58af2`) and Lavf 62.3.100 (`0x1deec2`). `libdav1d` has `1.5.3-0-gb546257f` at `0x17f99f`; `libbluray` has 1.3.2 at `0x352e8`. Stratospherix's build-identification string gives project 5.1 at `0x1e8800`, not a verified API version. Exact libnfs/libudfread/libass release versions: not established.
3. **Hardware and software decoding are separate candidates.** FFmpeg's arm64 configuration string in `libavcodec` at `0x1b9be43` enables libdav1d but disables its own VideoToolbox/AudioToolbox integration. The app independently imports `VTIsHardwareDecodeSupported`, `VTDecompressionSessionCreate`, `VTDecompressionSessionDecodeFrame`, `VTSessionSetProperty`, and FFmpeg decoder APIs. This supports an app-managed hardware path alongside FFmpeg; it does not identify selection precedence or fallback conditions. Codec descriptions for H.264 (`0xe71032`), HEVC (`0xe71dc9`), TrueHD (`0xe7337b`), E-AC-3 (`0xe5999e`) and PGS (`0xe911ce`) occur in libavcodec. Shipping decoder descriptions is not a complete tested device/codec matrix.

### Dolby Vision, HDR10+, rendering and display matching — partly answered

4. **Dolby Vision has explicit descriptors and metadata.** `A` contains `DolbyVisionConfiguration.swift` at `0x2065050`, its `init(confRecord:trc:)` identifier at `0x20650e0`, and `addSideData(to:)` at `0x2065150`. The app imports `av_dovi_alloc` and `CMVideoFormatDescriptionCreateFromHEVCParameterSets`; it also carries `createDolbyVisionDescWithHevcDesc:dolbyVisionConf:` at `0x1f6e8bd` and a reshape-data property at `0x1f4bff9`. `L:787–788` exposes extended/limited Dolby Vision setting labels. Supported DV profiles, base-layer fallback, enhancement-layer handling and exact mode semantics: not found.
5. **HDR10+ is detected/represented.** Selectors `shouldProbeForHDR10PlusMetadata` (`0x1f3b6fb`), `probeForHDR10PlusMetadata` (`0x1faf0ea`) and decoder-result metadata fields (`0x1f89f4e`) exist in `A`. This establishes metadata probing/plumbing; it does **not** establish HDR10+ dynamic-metadata output to a display. A database-migration label at `0x201c334` is corroborating inventory, not a rendering algorithm.
6. **Two tone-mapping modes and custom rendering plumbing.** `L:750–752` labels custom Infuse and Apple HDR-color modes; `A` has `setupTonemappingWithDescriptor:` (`0x1f3b540`), `layerTonemappingEnabledForOptions:` (`0x1f97ead`) and tonemapping-function fields. Metal/CoreVideo/CoreMedia dependencies and `CAEDRMetadata` imports are present. The files named `FCMetalRenderingShader.metal` and `FCSharedMetalTypes.h` contain opaque bytes; diagnostics at `0x202bdf9` and `0x202be55` explicitly refer to encrypted resources. They were not decoded. Tone curve, luminance mapping, HDR-to-SDR behavior and precision remain unknown.
7. **Frame-rate awareness, not proven automatic matching.** `L:244–245` labels source and screen frame rates. `A` includes `RefreshRateHandler` (`0x2128940`), preferred/display refresh-rate fields and frame-rate properties. REA records CVDisplayLink imports for refresh-period measurement. These do not prove changing the display mode, start/stop restoration, fractional-rate policy or dynamic-range matching. This Mac artifact cannot establish Apple TV Match Content behavior.

### Audio and subtitles — partly answered

8. **Route-dependent passthrough/Atmos candidates.** `A` contains `FCPassthroughAudioDecoder.m` (`0x200eb77`), `FCPassthroughSPDIFMuxer.m` (`0x200f921`), AC3/DTS passthrough option selectors, and `canUseAtmosPlaybackForStream:playbackRate:routeService:` (`0x1f64e71`). Atmos enable/allow and support selectors exist; `L:706–707,733–734` supplies HDMI/AirPlay and passthrough settings. This supports distinct passthrough and Atmos eligibility plumbing, not the codec/route truth table. Whether E-AC-3 JOC or TrueHD Atmos is decoded, preserved, converted or unavailable on a given route is unresolved. FFmpeg's Atmos descriptions cannot answer that question.
9. **ASS/SSA and bitmap subtitle paths.** `FCASSSubtitlesDecoder` configuration and receive identifiers are at `0x204d214` and `0x204d2af`; libass log identifiers at `0x20db19c` / `0x20db1b5` establish a libass component. `FCFFMPEGSubtitlesDecoder` open/log identifiers at `0x1ffce80` / `0x1ffcefd`, the app import `avcodec_decode_subtitle2`, and `hdmv_pgs_subtitle` at `0x2066e40` support an FFmpeg PGS path. `FCMetalSubtitleRenderer` is represented at `0x1f1e223`. `L:163–165` has missing-font/import guidance, and `L:230` an HDR subtitle-brightness setting. Exact PGS composition, ASS animation/font fallback fidelity, scaling and renderer selection were not decompiled.

### Share types, discovery and setup — partly answered

10. **Protocol inventory.** `VFSProtocolType.m` / `FCGetNameForProtocol` identifiers at `A:0x2041347–0x20413f6` sit with names for FTPS, FTPES, SFTP, UPnP/DLNA, WebDAV, HTTPS WebDAV, generic HTTP, Emby and Jellyfin (`0x2041283–0x20412cd`). Separate SMB/NFS/FTP connection/browser/stream classes exist; Plex entry points are at `L:1461–1482`. This establishes packaged protocol support candidates, not that every one appears in the current Add screen or supports every operation.
11. **Cloud inventory.** The same protocol-name region has Aliyun Drive, Baidu, GuangYaPan, 115, 123yun, Dropbox, Google Drive, MEGA, OneDrive, pCloud and Yandex.Disk (`0x20412d6–0x204133b`). `L:1200` has iCloud Drive addition, and `L:1289` mentions Box in onboarding. **Box is only a resource mention in this pass**; its working protocol implementation was not established. Cloud-token renewal/error resources are at `L:303,315–318,336–337,369–370`.
12. **Discovery mechanisms.** Bonjour type strings at `A:0x1ff4a21–0x1ff4a4e` are `_ftp._tcp`, `_sftp-ssh._tcp`, `_smb._tcp`, `_nfs._tcp`, `_webdav._tcp`; adjacent `FCBonjourDiscoveryService` and NSNetService-browser/resolution diagnostics support discovery and failure handling. The main image also imports Network's Bonjour browser descriptor. UPnP discovery has M-search/notify identifiers and SSDP multicast `239.255.255.250:1900` (`0x2117e7a`), plus discovery callbacks (`0x1f75941`). `EmbyDiscoveryService.swift` and UDP broadcast/response diagnostics are at `0x205a0b0–0x205a290`. Port, broadcast cadence and Jellyfin reuse of that service: not found. A `NetBios` string at `0x20836b1` belongs to a generic address-family list, **not proof of NetBIOS share discovery**. WS-Discovery was not established.
13. **Add-share flow represented in resources.** `L:1111–1149` separates local/network/media-server entries, available shares/servers and saved shares; manual addition and share-detail resources represent protocol, address, name, account, username/password and advanced options. `L:1134,1137,1160–1164` adds workgroup, MAC address, path/base URL, port, QPS limit and a connection-check state. `L:1167–1174` represents connection success followed by folder-library inclusion, library mode, pre-cache and auto-scan controls. This is a resource-supported flow outline; exact screen ordering, validation and which fields each protocol shows were not observed. Packaged nibs for Discovery, ShareDetails and ConnectionSuccess corroborate the screen inventory.
14. **Credentials.** `FCNetworkShare savePasswordToKeychain` at `A:0x20465b6`, `restorePasswordFromKeychain` at `0x1fb8d41`, OAuth-keychain identifiers at `0x20093bc`, `UICKeyChainStore` and `SecItemAdd/CopyMatching/Delete/Update` imports support Keychain-based storage. Workgroup/protocol-version serialization keys and an SMB initializer at `0x2049463–0x2049558` identify SMB auth/config inputs. Exact Keychain accessibility class, access group, identifier composition, iCloud synchronization and removal semantics: not found; no live credential store was inspected.
15. **SMB versions/options.** SMB Auto, SMB1, SMB2, SMB3 and Legacy identifiers exist at `A:0x1ff1704–0x1ff1727`; these occur near analytics code, so they are not a verified menu/default. `L:1121,1126` establishes a version/legacy setting label; `connectedSMBDialect` and the imported `kSLSConnectionConfigSMBMode` establish configuration and negotiated-dialect plumbing. Stratospherix contains dialect strings 2.0.2, 2.1.0, 3.0.0, 3.0.2, 3.1.1 (`0x20b835–0x20b84d`), SMB3 encryption diagnostics (`0x20d59c–0x20d615`) and NTLMv2 rejection (`0x20d993`). No default dialect, negotiation order, signing policy or encryption requirement was verified.

### Browsing, indexing, matching and failures — partly answered

16. **Browsing and library inclusion differ.** `L:1168` directs folder selection into the Library via a star; `L:1170–1174` separately labels library mode, caching and auto scan, and `L:1393` represents library mode disabled. Protocol browser identifiers expose directory listing separately from stream creation: WebDAV at `A:0x20332f9`, FTP at `0x2049017`, modern SMB input-stream open/read at `0x1ffdc51` / `0x1ffde35`. Favorite indexing has `setIndexingForFavorite:enabled:` at `0x1f3a15c`. These support a distinction between a saved/browsable connection and indexed folders; exact recursive inclusion rules and defaults remain unknown.
17. **Folder parsing and metadata.** `FCSeriesTitleParser` is identified at `A:0x201496f`; nearby patterns (`0x20147c7–0x2014948`) represent season/episode notation, `1x02`-style notation, specials, season-folder numbers, episode-only and season-episode names. They support parsing candidates, not precedence or successful parsing of every variant. `FCMovieTitleParser` exists at `0x211b7b0`. TMDB service/request identifiers are at `0x200bbc4–0x200bc56`; NFO, FFmpeg embedded-metadata and other parser classes are also present. `L:552–557` describes per-folder local/online metadata choice, while `L:720–723` represents embedded/local artwork preferences. The resource describes local-folder mode using embedded information without online requests; its exact implementation and NFO precedence were not traced. Match-confidence thresholds and multipart/extras rules: not found.
18. **Scan/refresh and partial stages.** `FCShareIndexingState didStartIndexContentOf:atDepth:` (`A:0x2022e4d`) and subtree-state diagnostics establish hierarchical indexing bookkeeping. Incremental-fetch/indexing selectors are present. `L:454–475` represents content fetch, merge, metadata, artwork, Next Up, pending/failure and retry stages; `L:1377–1393` distinguishes scan-for-changes from metadata refresh and tracks last update/in-progress/never. Auto Scan exists, but its intervals, launch/background triggers, notification subscriptions and cancellation rules were not found. The InfuseSync suggestion at `L:1500` specifically presents a faster server-scan path; no plugin was installed.
19. **Offline/unreachable states.** `L:298–313` distinguishes permission/authentication, host resolution, connection, missing path and overloaded-server errors. `L:469–470` has indexing failure/check-and-retry; `L:321–322` points moved/deleted server files toward a server library rescan. Cache-loss/corruption/restoration resources are at `L:323–354`; cloud access revocation has separate reauthorization resources. These are state/message evidence, not a verified retry schedule, retained-catalog policy, deletion policy or offline-playback guarantee.

## Not found

- Exact decoder selection/fallback, complete codec matrix, DV profile/enhancement-layer support, HDR10+ output, tone-map algorithm and tested HDR/SDR correctness.
- Atmos codec/route matrix, TrueHD Atmos output, passthrough availability by OS/device, subtitle rendering fidelity and precise frame-rate/dynamic-range matching behavior.
- Proven NetBIOS or WS-Discovery; discovery cadence/ports for Emby; current UI visibility/defaults for every protocol; Box implementation.
- Credential accessibility/sync/deletion policy; SMB negotiation/signing/encryption defaults; exact field validation and add-screen order.
- Filename-pattern precedence, matching scores, extras/multipart policy, recursion limits, automatic scan schedule and stale/offline-item retention/retry policy.
- Native Infuse function behavior was not recovered. Its prior investigation's 600-second Ghidra timeouts were not repeated; this pass used Mach-O inspection and cheap artifact probes instead.

## What OpenStream should do

1. Keep AetherEngine's format detection, decode selection, display output and playback diagnostics separate; report the path actually selected.
2. Test hardware/software fallback with owned local fixtures for H.264, HEVC and AV1; library presence must not become a support claim.
3. Preserve DV/HDR10+/mastering metadata through demux/decode boundaries, and test output by device/OS. Do not advertise unverified enhancement-layer or HDR10+ output.
4. Make audio decisions from codec, device, route and playback rate; distinguish PCM decoding from bitstream passthrough and Atmos output.
5. Exercise PGS composition and ASS embedded fonts/animation with fixtures; make HDR subtitle brightness and legibility part of verification.
6. Treat discovered servers as suggestions; retain manual host/path entry and useful DNS/authentication/connection errors.
7. Keep source setup small: protocol-appropriate fields, a connection check, then browsing and explicit folder inclusion. A saved SMB connection should not automatically imply indexing every share.
8. Store credentials in Keychain, reference them by a stable source identity, and verify accessibility/forget behavior independently; never place secrets in serialized source URLs.
9. Record the negotiated SMB dialect in diagnostics, prefer the modern path, and make legacy selection an explicit user choice if needed. Keep credentials out of range-server URLs/logs.
10. Separate directory/change scans from metadata refresh; retain local filenames and provider IDs so matching can be corrected without rediscovering media.
11. Allow per-folder online/local metadata choices and preserve explicit matches; add parsing fixtures for season folders, specials, episode-only and season/episode names without importing Infuse regexes.
12. Keep indexed items when a share is temporarily unreachable, present a concise retry action, and update content/metadata/artwork progressively. Retry timing and retention are our policy proposals, not established Infuse behavior.

## How this was done

- Read the complete Apple AGENTS.md, worker-B spec, prior reference report and reverse-engineer-anything skill. Usage board advised Codex first. Read-only SSH targeted the copied artifacts on Dev-Mini; scratch remained in `/tmp`.
- REA `open_binary(A)` and `inspect_macho` worked without Ghidra auto-analysis. Parsed Info.plists, decoded UTF-16 localization, inspected `nm` imports and binary printable-string offsets in Python. No library or target function was executed.
- Initial UTF-8 reads of `Localizable.strings` failed with `UnicodeDecodeError`; decoding UTF-16 resolved that. Shader/header-named files also failed UTF-8 decoding; their encrypted-resource diagnostics explain the opaque bytes, and investigation stopped there.
- UI decoding dead ends: opening the standalone ShareDetails nib returned `target_unavailable`, reason `unsupported binary format`; opening the app bundle returned `capability_unavailable` because Ghidra rejects a universal Mach-O (Hopper executable missing, IDA not configured). `inspect_keyed_archive(path=nib)` then returned `target_unavailable: No app is open`. No setup/install or decryption was attempted; flow claims remain resource-supported.
- Native sessions were closed after inspection. No builds, sims, playback, external services, uploads or source-code changes were performed. REA Evidence is session-scoped; the digests/paths/offsets above provide durable replay anchors.
