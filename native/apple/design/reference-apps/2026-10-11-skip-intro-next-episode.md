# Skip markers and next episode: five reference apps

Static REA trial, 2026-10-11. These are findings from the shipped artifacts below, not observations of running players. No apps/APKs were launched or installed, no accounts or network playback responses were accessed, and no DRM or encryption was bypassed. **Not found** means this investigation did not establish the behavior; it does not mean the app lacks it. Recommendations are OpenStream policy proposals, not copied implementations.

## Apple TV

1. **Marker source.** `FUN_10048f60c` reads HLS metadata and builds entries containing label, start, duration and target. Associated strings are `com.apple.hls.skip.count` at `0x100f62674`, and `com.apple.hls.skip.%d.{label,start,duration,target}` at `0x100f6268d`, `0x100f626a9`, `0x100f626c5`, `0x100f626e4`. This is evidence for supplied HLS markers, not local intro fingerprinting or a fixed intro offset. Evidence: `ev_8acc93aa5a5e8e40b42fe72869a24fe7933734eef6fb063af2672df5a511351e`, strings `ev_fe932c0ecb8aaf70749383ee1347b8ddebb8c4d7ed9b626107f2d26275efbda5`.
2. **Skip prompts/action.** The entries carry enough data for a timed skip window, but assigning that window to actual button visibility would be an inference. Exact appearance, disappearance, dwell time, early dismissal and separate recap/credits handling: **not found**. `VideoHUDContentShimModel::doSkipToTimecode:skipActionName:` at `0x10043c7d0` performs the seek with scrubbing state changes. Evidence: `ev_aac82e8612cee15cc9721d554e164fa7cc0cb277de42d2e9aecf69c22c795071`.
3. **Post-play boundary.** `FUN_10056b58c` reads `com.apple.hls.up-next.start` (string at `0x100f691ec`) in seconds and converts it to milliseconds. When no valid entry supplies the boundary, a duration greater than 30,000 ms permits a duration-minus-15,000-ms fallback. Metadata/duration availability still guards initialization. `FUN_10056a8fc` compares current time against that boundary, sets a once-fired flag and emits `_TVPlaybackEngineVideoDidCrossPostPlayBoundaryNotification`. These are boundary calculations, **not proof of a fifteen-second countdown**. Evidence: `ev_aa95ca8fe74bc07a9f39fe5782f1c476c6690b398f6c3a7f27c84a7bc409ba79`, `ev_1e1362c5f068407ca4b4673931ab78f1cc14149f862fa9934e11565a8a633551`. `TVAppPlaybackEngine::setPostPlayMode:` at `0x10056da98` forwards a mode value; it does not expose the timer (`ev_6cac96f541db90884aa93d91fd025169f1e68b54fc77fc6eb86476a7267116f3`). Countdown length, zero action, remote behavior, last-episode/movie routing: **not found**. Unrelated `AskUserNSAlert` countdown procedures were excluded.
4. **Settings.** `TVGeneralPrefsViewController` has `autoPlayRecommendedItems` (`0x10012b2f0`), `autoPlayNextVideoStackView` (`0x10012b318`) and description (`0x10012b340`) accessors; `autoPlayNextVideo` appears at `0x100f40aff`. ## Plex

All offsets in this section refer to `web-client/js/main-8792-e90a21a5fe7ae941e8eb-plex-4.160.0-75ddd7b.js` (SHA-256 `e59d55e322abe4dcddf487fbffddc2e541330f5aa1339a158636f58a883edc01`). REA application evidence: `ev_21ec6cc5d355de0a96cef5f79675990f931fa5f1cf3e9b32215137e198eaa32f`; module view: `ev_0d54683dc54f35531193380c814cffb4b4fe3866306c85241fb9047ebc170fe4`. Locations were refined by direct static text inspection of that same bundle. REA parsed 202 JS files without parse failures, but semantic graph expansion was partial; this is not an exhaustive application analysis.

1. **Marker source.** Metadata carries a `Marker` array (~196765); `augmentResponse` / `convertMarkers` (~200468 / ~202462) normalize it and parse start/end offsets as integers. Metadata and play-queue requests set `includeMarkers:1` (~288851 / ~305524). This establishes a server-metadata path; no local detection was found. Constants identify commercial, credits and intro (~1179464). The selector (~1432179) filters eligible marker types with feature/library gates and selects `startTimeOffset ≤ positionMS < endTimeOffset`. A recap-label branch exists, but actual recap-marker selection was **not found** in this selector.
2. **Skip visibility/action.** Function `vk` (~1262700) closes the affordance when the marker is missing, the position leaves its interval or forced hiding applies. Clicking seeks to the marker end rounded to seconds. Polite controls hiding starts a deadline at current playback position +10 seconds; this uses **playback time**, not an independently established ten-second wall-clock timer. A repeated-controls-hide state forces immediate hiding; a near-end guard hides an activated button when less than 500 ms remains. Marker identity changes reset dismissal bookkeeping. The button has autofocus and stops Enter keydown/keyup propagation before its press action, avoiding an additional parent action. The caller at ~1428440 passes the controls-hide conditions. No universal always-visible ten-second dwell should be inferred.
3. **Post-play/countdown.** In `LO.onEnd` (~1188301), remaining multipart segments advance first; repeat-one/repeat-all special cases are handled before next-queue behavior. With a next item (or eligible repeat-all), `kO` (~1184697) decides whether to show post-play or advance directly. It requires eligible video/local-player conditions and duration at least `minSecondsForPostPlay` (default 300 seconds, ~1195316), unless `displayPostplay` overrides that duration test. The show action (~350579) loads optional hub content, then marks post-play visible and pauses. This inspected route begins at **playback end**, not at the credits marker.

   `YH`/`ZH` (~1388500) initializes `secondsLeft` to 10. When autoplay is enabled, a one-second interval decrements it; reaching zero calls `onPlay`. Disabling clears the interval and resets the counter to 10; enabling starts it; unmount clears it. `XH` (~1390812) wires the play action and autoplay checkbox. `eW` (~1391176) uses the next queue item (`fC.A(1)`); absent a next item, this component renders no post-play payload. A manual next-item button is present. Prompt-specific remote/Back behavior: **not found**. Last queue item without repeat ends playback; the inspected branch is queue-based and has no episode-only check, so a movie with a queued successor can use it. Separate recommendation/finale routes: **not found**.
4. **Settings.** Settings initialization sets Auto Play true (~3025617). The player settings expose it (~1406071), and the post-play checkbox can toggle it (~1390812). Automatic intro/credits-skip controls and still-watching limits: **not found** in the inspected paths/searches.

## Paramount+ Android TV

## What OpenStream should do

- Use approved chapter markers through a normalized marker model with explicit type/start/end/seek target, inspired by Apple TV's supplied marker records and Plex's metadata normalization. Validate bounds against duration. Keep intro fingerprinting tabled; neither the task nor these findings authorize it.
- Show an intro/recap/credits affordance only for a valid typed marker at the current playback position. Use a documented half-open interval, following Plex's recovered rule; do not reinterpret Paramount+'s preview markers as recaps.
- Seek directly to the validated marker target/end and dismiss that marker's affordance after activation, following Apple TV's skip action and Plex/Paramount+'s endpoint seeks. Track dismissal by marker identity so another marker or a deliberate replay can have its own state.
- Separate marker eligibility from transport-control visibility. Plex provides explicit polite/forced-hide handling; define OpenStream's policy clearly and test it with pause, seek and repeated controls hiding rather than blindly adopting its playback-time deadline.
- Separate the post-play boundary from the countdown. Apple TV supplies an explicit HLS boundary and a guarded near-end fallback; Plex supplies an end-of-playback path. For OpenStream, prefer an approved credits chapter when available and use playback end otherwise. Do not invent a fixed intro offset or treat Apple's 15-second boundary as its countdown.
- Keep existing `autoPlayNextEpisode` default on. Use a **proposed 10-second** cancellable next-episode countdown, inspired by Plex's confirmed counter, plus an immediate play action. Turning autoplay off should stop/reset the countdown while preserving manual next-episode access.
- Resolve a playable successor before starting the countdown. Follow Plex's queue checks: stop at the last episode, handle multipart/repeat explicitly, and require an explicit queue successor for movies rather than assuming “next episode” exists.
- Let Back cancel/dismiss OpenStream's post-play prompt and ensure one press triggers one action. Paramount+'s state-dependent end-card dismissal and Plex's Enter propagation handling support the interaction principle; their complete remote policy is not established here.
- If adding auto-skip settings later, keep intro and credits choices separate, inspired by Infuse's separate mode labels. Retain manual skipping as the baseline; any delayed/instant timing or inactivity threshold requires an explicit OpenStream decision. No Netflix still-watching limit was recovered to adopt.

## How this was done

- Read all of `native/apple/AGENTS.md`, the task specification, the project-level instructions and the live usage board. Loaded the `reverse-engineer-anything` skill and relevant native/Android/JavaScript guidance. Checked Dev-Mini's `~/Developer/.build.lock/owner` before heavy native work; no active build lock was found.
- Used the **REA MCP tools**, running on Dev-Mini through its configured SSH server. Working Android tools: `inspect_android_package`, `search_android_classes`, `inspect_android_class`, `inspect_android_method`, `trace_android_references`. Start with class inventory, then inspect exact classes/methods; some Paramount+ coroutine bodies required complete smali fallback. JADX headless 0.7.1; decompiler display signatures are not exact DEX descriptors.
- Working JavaScript tools: `analyze_javascript_application(input_path=<Plex web-client>, detail="summary", analysis_timeout_ms=120000)` and `inspect_analysis_view` for retained module pages/items. Direct static bundle searches supplied the precise character locations above. REA's semantic graph hit expansion/result-memory constraints; zero parse failures does not imply complete semantic coverage.
- Working native tools: `open_binary(provider_id="ghidra")`, `search_strings`, `search_procedures`, `xrefs`, `analyze_function`, `close_binary`; Ghidra 12.1.4. For Apple TV, searching `com.apple.hls.skip` and `com.apple.hls.up-next.start`, then following code xrefs, was more useful than searching only friendly function names.
- Supplemented REA with read-only SSH `plistlib`, ZIP/DEX inspection, `nm`, `otool`, checksums and bounded printable-string searches. Scratch-only DEX string/field-reference probes selected obfuscated Paramount+ candidates; every behavioral conclusion above was checked against a REA method result. No target code was executed. Scratch stayed in `/tmp` on Dev-Mini.
- **Setup failures:** `decode_android_resources` failed for both APKs with `capability_unavailable` / `unsupported_provider`: selected `apktool` launcher not found; tool suggested configuring `REA_APKTOOL_COMMAND`. No installation was attempted. On Dev-Mini, `rg` was unavailable in the invoked SSH PATH; Python/grep served the bounded searches. The system Python lacked `hashlib.file_digest`; incremental SHA-256 hashing worked.
- **Native limitations:** Infuse's universal Mach-O was rejected by Ghidra with `architecture_unsupported`; Hopper's executable `/Applications/Hopper Disassembler.app/Contents/MacOS/hopper` was missing and IDA's `REA_IDA_MCP_CONFIG` was unset. `lipo -thin arm64` produced the scratch slice without changing the app. Infuse arm64 `search_procedures` and then a narrower `search_strings("fetchVideoMarkers")` each timed out (`provider_timeout`, 600,000 ms); the native session was closed after the retry, and the provider/setting findings remain string-only. Apple TV `decode_interface_builder` first required opening the `.app` rather than the executable; the bundle attempt with `max_documents=64` completed but exceeded the approximately 10-MB MCP transport ceiling (`resource_constraint`). Its interface output was not consumed, so no settings behavior is attributed to it. No software was installed.
- Reproduction entry point if MCP discovery is needed: `ssh dev-mini '~/Developer/bin/rea-mcp.sh cli …'`. Reuse the installed targets/engines, verify the build lock before Ghidra, inspect cheap candidate searches first, and close the native session before changing targets. No OpenStream builds, tests, simulators or source changes were required.
