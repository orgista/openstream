# Plex lessons for OpenStream

Topic 3b, 2026-10-11. Read-only comparison of the existing [Plex backend report](2026-10-11-plex-backend.md) with OpenStream's Apple source. Only this report was written. No builds, tests, simulators, app execution, network requests, binary analysis or uploads were performed.

## Comparison / summary

Plex's most useful lesson is to give discovery, identity, matching, user state and playback separate contracts. OpenStream already has many of those pieces: a persistent media index, progressive metadata, watched/unwatched events, Continue Watching removal, provider progress reporting, cached server shelves, chapter support and AetherEngine routing. The weaknesses are mostly where those pieces meet, rather than a need to reproduce Plex Media Server on a phone.

| Area | What is weaker today | Recommended rank |
|---|---|---|
| Library model + scanning | Scan completeness is not enforced at replacement; local enumeration truncates, while the active SMB walk is unbounded | 1, 7 |
| Filename parsing | Single episode coordinates; no explicit episode ranges, air-date identity, extras classification or multipart composition in the inspected pipeline | 5 |
| Metadata matching | Same-name/year heuristic without persisted confidence or a manual match record; IDs are lost between some projections | 6, 7 |
| Watched / Continue Watching / Up Next | Completion rules disagree across paths; finished-series row eligibility depends on progress that the store deletes | 2 |
| Home rows | Good ordering/paging policies already exist; Plex adapter exposes recent items rather than the richer hub surface | 9 |
| Markers | Embedded chapters work; no common typed provider-marker model or media-version provenance | 11 |
| Playback decision | AetherEngine handles local routing, but Plex adapter selects the first original part without server negotiation | 8 |
| Play queues | Episode handoff and a local continuous-channel queue exist; no general persistent/versioned playback queue | 10 |
| Offline / unreachable sources | Server caches survive failure; local Library groups are rebuilt without failed sources | 1 |
| Sync / backup | Substantial support already exists; progress and completion merge independently, and server reporting is best-effort | 3, 4 |
| Live TV / EPG | Strong IPTV guide/catch-up separation; mapping provenance could improve; tuner recording subscriptions are absent | 12 |

Ranks below are proposed implementation priorities, not authorization to change code. Effort: **S** = focused policy/adapter change, **M** = several components and integration fixtures, **L** = new model/protocol plus migration or lifecycle work. Risk refers to regressions, state migration and provider compatibility. Plex's offline and backup policies were not established by Topic 3; there is no evidence-based claim that Plex is better in those two areas.

## Findings with evidence locations

### Evidence convention and limits

A reference such as `S/AppleMediaIndex.swift:228` identifies a source line, not a runtime trace. Recommendations and predicted failure cases are explicitly design judgments or source-level inferences.

Plex evidence is inherited from the input report's numbered findings, with its exact artifact anchors repeated where useful. Its `M` is the packaged web client's `main-8792-e90a21a5fe7ae941e8eb-plex-4.160.0-75ddd7b.js` on Dev-Mini. Its binary offsets are raw universal-file offsets unless labeled VA. The input targets were PMS 1.43.4.10903 and web client 4.160.0; the retained REA JS parent is `ev_446f3aa47969330fb4dc9e49f614684ccff3af44f6111f94b52cf9247ac51faf`. This follow-up did not reopen targets or independently reproduce that analysis. Bundled legacy Python scanner/agent behavior must not be presented as verified current native Plex behavior.

### 1. Library model + scanning

**Plex:** Findings 1–6 distinguish enumeration/filtering, movie/series interpretation, matching and analysis. The shipped legacy scanner can model separate episodes sharing a file and stacked movie parts. Native scanner stage names corroborate separate concerns but not their exact order. PMS settings at `0x122f8ca–0x122fab6` distinguish folder notifications, partial/periodic scans and trash removal; defaults and deletion transactions remain unknown.

**OpenStream today:**

- `S/AppleMediaIndex.swift:49` stores a flat media record with canonical identity, availability, favorite and a progress projection. Availability hashes its lookup reference (`:29–45`) and merges one entry per source (`:114`). This is useful for discovery/privacy, but it is not a show/season/episode/media-version/part graph.
- Local ingestion uses a digest of source UUID plus relative path, classifies every file as `.video`, and labels MKV availability `.gateway` (`S/AppleMediaIndex.swift:507–526`). Actual Aether playback can handle MKV directly, so that index capability is not a verified playback decision.
- Grouping is a separate in-memory model: show title/year/source, dated movie title/year/source, otherwise individual file identity (`S/AppleLibraryShelves.swift:10–40`). Different copies can collapse into one movie card while remaining selectable (`S/AppleLocalLibraryStore.swift:199–205`).
- The local folder scanner returns only an array, silently stops at 5,000 files, and skips files whose resource lookup fails (`S/AppleLibrary.swift:103–143`). Repository replacement removes a source's previous availability before inserting at most 10,000 records (`S/AppleMediaIndex.swift:226–256`). Its comment promises a complete bounded snapshot, but the signature carries no completeness proof.
- The active Library SMB path is **not** the bounded `AppleSMBLibraryScanner`. `S/AppleLocalLibraryStore.swift:284–287` calls `AppleSMBNetworkLibraryScanner`, which calls a recursive directory walker (`S/AppleNetworkShare.swift:676–691`). That walker has visited-path deduplication but no item/folder/depth limit or explicit cancellation check in its loop; a child load error propagates (`:102–121`). The separate bounded scanner exposes skipped-folder/limit status and progressive results (`S/AppleSMBLibraryScanner.swift:3–29,63–133`); those guarantees are not wired into this reload.
- Startup publishes saved local groups, then conditionally scans (`S/OpenStreamRootView.swift:510–525`). The freshness gate is ten minutes and keyed there by source IDs (`S/AppleLaunchWorkPolicy.swift:10–24`); Library has pull refresh (`S/AppleMediaSourceViews.swift:3353–3359`). No local filesystem-notification/changed-folder job was found in these entry points.

**Gap and change:** Rank 1: enforce complete/partial/failed scan results before removal. A 5,001-file folder can lose previously known items when its bounded result replaces the source projection; this is a source-level inference, not a reproduced loss. Add bounded cancellation-aware SMB traversal and per-folder completion. Rank 7: retain separate logical title/episode and playable file/version/part identities, with aliases for existing saved-state keys. Do not replace the lightweight local index with a server-scale system.

### 2. Filename parsing

**Plex:** Legacy `Plex Series Scanner.py:8–19,48–79,211–291` handles strong season/episode patterns, ranges, air dates and guarded weaker matches. `Plex Movie Scanner.py:17–134`, `Stack.py:11–68`, and `VideoFiles.py:198–238` distinguish discs, multipart, versions, extras and samples. These are evidence for categories to handle, not an algorithm to copy or proof of current native precedence.

**OpenStream today:** `S/AppleLibraryTitleParser.swift:13–44` parses `S…E…`, `…x…`, Season/Episode folder text and a `shows` parent; it returns one season and one episode. It handles hashed/disc-style names using parent folders (`:56–78`), removes release tags while protecting numeric titles (`:80–105`), and groups/sorts parsed files (`S/AppleLibraryShelves.swift:10–40`). Local episode projection substitutes season 1 and enumeration index + 1 when coordinates are absent (`S/AppleLocalLibraryStore.swift:417–465`). Folder scanning filters extensions/hidden/packages, not an explicit extras or multipart role (`S/AppleLibrary.swift:94–143`); the active SMB scanner likewise filters by extension (`S/AppleNetworkShare.swift:692–708`).

**Gap and change:** Rank 5: return parsing provenance and confidence, optional episode ranges/air dates, and file role. Unnumbered files should not silently become trusted episode numbers based on the ordering of available copies. Distinguish multiple versions from sequential movie parts; do not auto-chain files merely because cleaned titles match. Use owned fixtures for `S01E01-E02`, date episodes, specials, extras, samples, numeric titles, Unicode, disc folders and part/disc names. Unknown names should remain playable as files while metadata/episode identity stays uncertain.

### 3. Metadata matching

**Plex:** Finding 5's bundled agent ranks and deduplicates candidates, prioritizes explicit IDs and has TMDB fallback (`PlexMovie.bundle/Contents/Code/__init__.py:344–463`). Its 100/98 scores are legacy-specific, not calibrated confidence values for OpenStream.

**OpenStream today:** `S/AppleLibraryMetadataResolver.swift:112–140` requires normalized equal title/type; exact year wins, otherwise a single same-name result is accepted or the nearest year wins. In add-on-enabled builds it searches Cinemeta then enabled add-ons; TMDB and OMDb credential lookups follow (`:143–205`). TMDB external-ID lookup can convert the result to IMDb identity (`:211–229`). Resolution has a four-request budget, one-hour negative/seven-day positive TTL and schema invalidation (`:70–94`), but local store resolution stops once in-memory metadata exists (`S/AppleLocalLibraryStore.swift:265–270`). The cache key uses path and size, not file modification/version (`S/AppleLibraryMetadataResolver.swift:70–72`). Plex GUIDs decode into IMDb/TMDB/TVDB helpers (`S/ApplePlexClient.swift:161–174`), but its catalog mapper uses `ms:<source>:<ratingKey>` and does not forward those IDs to the catalog item (`S/AppleMediaServerLibraryStore.swift:120–164`).

**Gap and change:** Rank 6: persist an owned match record with explicit IDs, candidate evidence, provider, confidence/ambiguity and a user override, independently of transient artwork cache. Preserve an override across rescans and file renames through the identity migration in rank 7. Allow a targeted refresh to revalidate stale in-memory metadata. Keep the intentional tolerance for production/release-year disagreement; returning to strict year equality would regress the documented local matching case. No persisted manual-match path was found in the inspected local matching pipeline.

### 4. Watched state, progress, Continue Watching and Up Next

**Plex:** Findings 7–9 distinguish position, count and last-viewed time; completion can use configurable percentage/credits. Continue Watching has window/count/premiere settings, and the client requests server eligibility (`M:440482`, `M:284383`). The exact default percentage and full On Deck predicates are unknown. Removal uses a server-advertised action (`M:3099716`), not a universal hardcoded path.

**OpenStream today:**

- Local resume requires at least 15 seconds; completion is 95% **or** at most 30 seconds remaining (`S/ApplePlaybackStore.swift:3–41`). Progress names its episode part separately. Completed saves delete resumable progress and add watched history under the part identity (`:211–239`). Watched/unwatched events and removal timestamps already exist (`:136–184`).
- Continue Watching filters the index's fractional progress or `isUpNext`; that latter requires a **saved complete progress entry** with a series episode ID (`S/AppleContinueWatchingResolver.swift:57–85`). Discover passes the current store entry to it (`S/AppleDiscoverView.swift:579–592`). Since normal completion deletes that entry, the branch does not establish ongoing eligibility after a real completed save. After index progress synchronization (`S/AppleMediaIndex.swift:656–663`), there is no fraction to keep the show either. This is an integration risk inferred from executable source; comments claiming the show stays are insufficient evidence.
- Local Library Continue Watching likewise requires resumable file progress (`S/AppleLocalLibraryStore.swift:240–258`). The title page has a real Up Next algorithm: regular episodes after the last completed episode, specials excluded unless no regular episodes, and a start-over fallback when everything is finished (`S/AppleStremioMetadataClient.swift:238–267`). Discover calls it with watched history (`S/AppleDiscoverView.swift:6722–6737`). Thus next-episode selection exists even when a home-row entry can disappear.
- Plex adapter obtains `/library/onDeck` (`S/ApplePlexClient.swift:416–419`) and contributes it to the server resume row (`S/AppleMediaServerLibraryStore.swift:265–268`). Its detail conversion only creates user data when both offset and duration exist (`:617–624`), so a `viewCount` without offset can lose watched state in that projection.
- Server resume/stop/scrobble code uses 95% without the local 30-second rule (`S/AppleMediaServerLibraryStore.swift:500–508,540–542,564–579,750–754`). Jellyfin/Emby merged resume uses maximum local/server position rather than recency (`:488–497`); the Plex branch uses server offset alone. A newer deliberate rewind or a failed server update can therefore disagree with local state.

**Gap and change:** Rank 2: one explicit policy for local completion/series continuation, plus provider-authoritative watched fields for server sources. Derive the completed episode's successor from watched activity and episode availability; distinguish an exhausted show from an intentional rewatch. Persist last activity independently of resume deletion, and define expiry/suppression without adopting an unverified Plex default. Test save → completion → index sync → row resolution, rather than only constructing complete resolver inputs. Decode provider watched count even when no offset exists. Rank 3 addresses cross-device consistency; rank 4 addresses remote reporting durability.

### 5. Home rows

**Plex:** Findings 10–11 show `/hubs`, section hubs and management, plus recent/released/unwatched/actor/director/genre/collection templates (`M:180388,1987792`; PMS `0x11733fa–0x11745d1`). Neither their presence nor the request code establishes a universal default row order.

**OpenStream today:** Discover assembles Continue Watching, resolved Library, server shelves, Top Picks, optional Top 10 and catalog rails; user ordering wins, otherwise presentation rhythm can reorder them (`S/AppleDiscoverView.swift:737–765`). Catalog policy removes empty/inactive rows and duplicate headings and establishes deterministic title order (`S/AppleCatalogShelfPolicy.swift:28–64`). Catalog store retains sections, loads pages and merges bounded results (`S/AppleCatalogStore.swift:879–908,1022–1058`). Local store memoizes sorted groups by content revision (`S/AppleLocalLibraryStore.swift:95–104,222–238`). Plex loading requests On Deck and section recently added; the client caps recently added at 30 (`S/AppleMediaServerLibraryStore.swift:265–285`; `S/ApplePlexClient.swift:422–430`). Plex catalog mapping drops genre/rating (`S/AppleMediaServerLibraryStore.swift:153–163`), whereas generic server items can form genre shelves (`:212–220`).

**Gap and change:** Rank 9: adapt supported Plex hubs into OpenStream's existing row contracts, keeping server eligibility and paging metadata; retain local fallback when the server does not support a hub. Refresh affected rows on progress/catalog changes. Avoid creating duplicate rows merely to match Plex's inventory. Keep Netflix as the Home visual reference and preserve the owner's row rules; Plex informs data eligibility here, not visual redesign. The existing ordering, empty-row and paging work should be retained.

### 6. Markers

**Plex:** Findings 12–15 separate audio fingerprint output, season-level intro orchestration, credits processing and per-part commercial EDL import. Fingerprinter function evidence `ev_2be31176533efac71afb0de78a56dc3b55568f8acc7952698859a0197c152902` establishes output formatting, not similarity matching. Detection quality, exact schedule and thresholds remain unresolved.

**OpenStream today:** `S/AppleChapterMarkers.swift:3–19` models chapter title/start/end. Intro selection is conservative whole-name/duration matching; scrubber fractions reject invalid positions/duplicates (`:43–99`). Aether adapter exposes engine-probed chapters (`S/AetherPlaybackEngine.swift:137–146`). No provider chapters/intro/credits marker fields appear in the inspected `ApplePlexItem` decoder (`S/ApplePlexClient.swift:67–115`), and playback hints there do not import them (`S/AppleMediaServerLibraryStore.swift:766–776`). The current chapter type has no kind, provenance or media-version field.

**Gap and change:** Rank 11: introduce a validated marker envelope separating chapter/intro/credits/commercial types, origin, media part/version and final-credit semantics; first populate it from approved embedded chapters. Continue reading only known marker boundaries; never infer an intro merely from elapsed time. Server-marker import and credits-aware completion are follow-up scope decisions, not automatic approval from this report. **Intro fingerprinting remains tabled.** Commercial detection and ML credits processing are not justified additions to the Apple client.

### 7. Playback decision: direct play, remux and transcode

**Plex:** Findings 16–17 show client profile/container/codec/audio/subtitle checks, independent stream choices and a server `/video/:/transcode/universal/decision` request (`M:490994–499000,531694–535000`). A decision timeout has a local fallback in the packaged client; this is not evidence that arbitrary unsupported content becomes playable.

**OpenStream today:** Aether receives load options and track preferences and reports native/loopback, software or audio-only presentation (`S/AetherPlaybackEngine.swift:286–300,896–902`). `ApplePlaybackPreparer` explicitly bypasses AVAsset inspection for the OpenStream engine; its alternative route can use native compatible-file export or a configured gateway session (`S/ApplePlaybackPreparer.swift:94–122,150–197`). Engine creation and exhausted native candidate handling already have bounded fallback policies (`S/ApplePlaybackEngineFactory.swift:13–30`; `S/ApplePlaybackEngineFallback.swift:32–71`). This app is not limited to original-file playback.

SMB playback bridges original bytes over loopback; it validates ranges, sends 206/416 and streams chunks (`S/AppleSMBRangeServer.swift:16–19,214–246`). The Library SMB route obtains that URL before creating the playback request (`S/AppleLocalLibraryStore.swift:481–487`). The bridge is transport, not a remuxer/transcoder.

The Plex adapter, however, flattens media wrappers into parts (`S/ApplePlexClient.swift:112–115,164–165`), picks `parts.first` and requests its original key (`S/AppleMediaServerLibraryStore.swift:731–776`; `S/ApplePlexClient.swift:435–438`). It does not negotiate a server profile or choose an alternate version/part composition. Generic media-server playback asks PlaybackInfo but selects only a direct-play/direct-stream source (`S/AppleMediaServerLibraryStore.swift:780–792`). The inspected Apple code delegates the internal remux/decode algorithm to AetherEngine; this pass did not inspect its package checkout.

**Gap and change:** Rank 8: preserve media versions and stream descriptors, then create a structured decision with video/audio/subtitle outcomes and reason codes. Prefer the working original/Aether route; request server conversion only when required by codec, route or bandwidth. Bound provider decision timeouts and validate any fallback against actual capabilities. Add fixtures for unsupported audio, subtitles requiring conversion, remote bitrate limits, multipart and engine-construction fallback. Playback diagnostics should distinguish byte transport, local remux/software decode and remote conversion. Do not claim SMB range delivery or `.gateway` index labeling proves transcoding.

### 8. Play queues

**Plex:** Finding 18's queue has server ID/version, stable item IDs, selection and a loaded range, with POST/PUT/fetch/move operations (`M:283700,305524,705606–706950`). Complete repeat/autoplay/end-of-part behavior was not recovered in Topic 3.

**OpenStream today:** `AppleNextEpisodeContext` carries one successor callback, title and track carry-over (`S/AppleNextEpisodePolicy.swift:9–18,144–213`). Prompt timing is the final 20 seconds, with dismissal and autoplay setting respected (`:65–140`). Discover resolves the successor's own sources on a fresh coordinator while keeping the ending presentation until handoff (`S/AppleDiscoverView.swift:6016–6034`). A genuine local continuous-channel queue exists: selected channel/item IDs, cyclic advance and Up Next (`S/AppleLibraryTV.swift:37–86`). It is volatile and limited to local programs (`:3–19,27–32`). These are useful implementations, but not a general persistent/versioned queue or Plex play-queue adapter.

**Gap and change:** Rank 10: unify stable queue item identity, cursor, source resolution and handoff state before adding reorder/shuffle/repeat. Persist logical descriptors, not URLs/credentials. Keep the existing one-handoff guard and language-based carry-over. Add part boundaries and distinguish the loaded queue window from total size if provider queues are supported. Do not discard the existing local queue or make server-backed queues mandatory for local playback.

### 9. Offline and unreachable sources

**Plex:** Topic 3 explicitly did not establish offline-source retention, deletion or reconciliation. Playback's offline flags/timeouts (finding 17) do not fill that gap.

**OpenStream today:** Startup can render `LibraryGroups-v1.json` filtered to active sources (`S/AppleLocalLibraryStore.swift:57–93`). Reload collects files only from successful sources, records source failures, then assigns `groups` from that collection and overwrites the snapshot (`:273–299,323–327,393–415`). Index writes occur only for successful scans (`:338–350`), so an unreachable source can remain in the media index while disappearing from Library groups. Cancellation/failure is not the same as explicit removal, but the projections diverge. The active SMB walker aborts on any child load error, as noted in area 1.

By contrast, media-server reload retains that source's previous shelves/resume items on failure and persists sanitized display state (`S/AppleMediaServerLibraryStore.swift:374–409,448–469`). Local reload incorporates downloaded records (`S/AppleLocalLibraryStore.swift:302–320`); server library exposes a local download playback request (`S/AppleMediaServerLibraryStore.swift:698–704`). Explicit source disable/removal has separate index availability cleanup (`S/AppleMediaIndex.swift:263–277`).

**Gap and change:** Rank 1: merge each successful source result into the last good snapshot, retain failed/partial subtrees as stale, and remove files only following a complete successful enumeration of their scope. Store last attempt, last successful verification and reachability separately. Keep stale content discoverable, resolve a usable download/alternate source before network preparation, and provide a concise retry/error at the point of play. No scanner failure should be interpreted as user deletion. This is an OpenStream consistency requirement, not claimed Plex parity.

### 10. Sync and backup of state

**Plex:** No persistence schema, backup format or cross-device conflict policy was established in the input report. Server-owned queues/progress APIs demonstrate server involvement, not backup guarantees.

**OpenStream today:** Configuration includes sources/tombstones, settings, progress, watched/unwatched history, watchlist, ratings and Continue Watching removals (`S/AppleConfigurationSnapshot.swift:67–116`). Progress merges by latest timestamp, watched events merge independently, and removal events merge separately (`:189–200`). Cloud export bounds entries and bytes (`:203–233`). Backups seal snapshot plus secrets with AES-GCM, using iCloud Keychain or passphrase mode (`S/AppleBackupEnvelope.swift:13–22,50–108`). Restore applies progress, then watched history and removals (`S/AppleConfigurationController.swift:446–453`). Source credentials/bookmarks are treated separately from portable state; sync includes empty-publish protection and delayed Keychain retry (`S/AppleConfigurationSyncPolicy.swift:69–80`).

Two integration gaps remain. Progress deletion on completion has no corresponding progress tombstone; restore unions incoming progress, and watched restore does not reconcile/remove older progress (`S/ApplePlaybackStore.swift:221–231,373–403`). **Inference:** device A's older partial progress can return after device B completed an item, even while watched history says complete. A genuine later rewatch must remain valid, so blindly clearing every watched item's progress is also wrong. Local file identities depend on path/source and will not automatically survive rename or source re-addition (area 1).

Remote reports run in separate Tasks; failures are logged with no durable retry queue in that handler (`S/AppleMediaServerLibraryStore.swift:518–559`). The stopped-session guard is set before delivery succeeds. A completed offline play or lost stop report can leave provider state behind local state. Plex resume currently favors only server offset (area 4).

**Gap and change:** Rank 3: reconcile progress with timestamped completion/reset events and test old-device return, completion, deliberate rewatch, rewind and unwatch. Migrate identities without throwing away current watched/removal history. Rank 4: add a bounded, ordered, coalesced remote-report outbox with session identity, retry policy and provider refresh/reconciliation; preserve terminal events until success or an explicit terminal outcome. Keep existing encrypted backups, credential sanitization and tombstones. Do not sync generated library caches as authoritative user state or claim Plex backup behavior we did not recover.

### 11. Live TV / EPG

**Plex:** Findings 19–20 separate tuner discovery, channel maps, EIT/XMLTV inputs, tune operations and recording subscriptions (`M:3150314,3160934–3162855,335884,264615`; PMS `0x11f441c–0x11f4a89`). New-only/all-airings and recording padding exist; conflict, retention and tuner-sharing policies remain unknown.

**OpenStream today:** IPTV guide store separates XMLTV and Xtream configurations, keys caches by source/channel and refreshes visible channel IDs (`S/AppleIPTVGuideStore.swift:26–45,63–90,105–145`). XMLTV uses a six-hour expiry and conditional requests; Xtream channel cache expiry is fifteen minutes (`:38–45,156–185`). Manual channel mapping wins, followed by exact/name matching; per-channel/source time correction is applied before a staged commit (`:169–214`). On failure previous guide data survives (`:229–232`). Matching rejects ambiguous normalized names and returns confidence (`S/AppleIPTVGuideMatching.swift:16–43`).

Start Over/catch-up depends on provider archive attributes and archive-window support, not an invented local recording (`S/AppleIPTVCatchUp.swift:33–65,108–178`). Live seeking uses the player's actual seekable span and live edge (`S/AppleLiveSeekPolicy.swift:3–12,60–74,112–121`), independently of the request's default buffer policy. No tuner-discovery/recording-rule/recording-conflict model was found in the inspected Apple source; `dvrWindowSeconds` is a live buffer hint, not a persistent recording subscription.

**Gap and change:** Rank 12: persist/inspect mapping origin, confidence, provider ID, fetch/coverage and applied time shift, keeping manual assignments authoritative. Existing cache retention and transactional guide replacement are patterns to reuse for library scans. Recording is a separate large product/backend project: define recurrence, padding, conflicts, retention and guide-change behavior before any implementation. Keep Live's Paramount+ visual reference and Provider Lineup/My Channels options; Plex's tuner UI is not a replacement design brief.

## Not found

- Plex's current native parser/matcher precedence, full Continue Watching predicates/default completion percentage, hub default order, full server transcode decision, marker quality and DVR conflict policy remain unknown exactly as in the input report.
- Plex offline retention, backup and sync behavior was not recovered; areas 9–10 identify OpenStream requirements without asserting competitor superiority.
- No runtime failure reproduction, timing measurement, provider compatibility test, end-to-end iCloud round trip or engine capability matrix was performed. Predicted loss/reconciliation cases above are source-level inferences.
- No general persistent playback queue, local manual-match record, local folder notification scan job, or tuner recording subscription was found within the inspected Apple source paths. This is bounded source coverage, not proof about every platform/backend in the repository.
- Internal AetherEngine remux/transcode/codec algorithms were not examined. Apple adapter code proves delegation and exposed routes, not complete codec support.
- Resolver tests and comments are not proof that completed saves retain a home-row successor. The save → index → row lifecycle needs verification in a later code task.

## What OpenStream should do — ranked change list

1. **Make scans safe to commit and retain offline Library content** (areas 1, 9). Complete/partial/failed scoped snapshots, bounded SMB traversal, cancellation, stale retention and per-source successful-scan stamps. **Impact: very high; effort M; risk medium.** Acceptance: >5,000 local files, >10,000 SMB files, denied child, unreachable root, cancellation and a genuinely deleted file preserve the right records; an incomplete attempt cannot claim a fresh complete scan.
2. **Unify completion and derive ongoing series eligibility from activity** (area 4). Provider watched fields remain authoritative; local completion, last activity, successor availability and suppression become explicit policies. **Impact: very high; effort M; risk medium.** Acceptance: a real completed episode save still offers the available successor; no bar resumes a completed episode; finished shows and specials follow documented rules; short-runtime and 30-second/95% boundaries agree.
3. **Reconcile progress, completion and reset during sync** (area 10). Timestamped terminal/reset events prevent older partial progress from returning while permitting a later rewatch. **Impact: high; effort M; risk high.** Acceptance: old backup/offline device, completion, rewind, rewatch, unwatch and cloud trimming converge deterministically without erasing newer activity.
4. **Deliver remote progress reliably** (areas 4, 10). Ordered/coalesced outbox, bounded retry and server reconciliation; stop/scrobble failures remain actionable. **Impact: high; effort M; risk medium.** Acceptance: failed stop, reconnect and back-to-back episodes preserve order and final state; no duplicate play count; local newer progress is not blindly replaced by stale provider offset.
5. **Expand parsing as owned policy with uncertainty** (area 2). Episode ranges/air dates, extras roles, multipart versus versions and confidence; no guessed trusted episode from copy ordering. **Impact: high; effort M; risk medium.** Acceptance: owned parser/grouping fixtures cover the named formats and retain ambiguous playable files without misidentifying them.
6. **Persist matching evidence and correction** (area 3). Explicit IDs, ranked candidates and manual overrides survive rescans; targeted refresh can renew in-memory results. **Impact: high; effort M; risk medium.** Acceptance: duplicate titles, year mismatch, wrong initial match and cache-version change remain correctable without losing progress.
7. **Separate logical items from files/versions/parts** (areas 1, 3, 7, 10). Preserve provider GUIDs; add episode/media relationships and old-key aliases; keep private transport references outside the index. **Impact: high; effort L; risk high.** Acceptance: rename/version/provider remapping retains user state; two parts chain deliberately, two versions remain alternatives. Design migration alongside ranks 2–6, stage rollout separately.
8. **Negotiate playback with explicit stream decisions** (area 7). Preserve version descriptors; compare Aether/device/route capabilities; use bounded provider decision and conversion fallback with reasons. **Impact: high for difficult/remote media; effort L; risk high.** Acceptance: video/audio/subtitle outcomes, multipart, bandwidth and fallback paths are verified independently. Do not duplicate Aether's remux pipeline.
9. **Use richer provider hubs through existing row policies** (area 5). Eligibility, paging and affected-row refresh, with existing custom order and empty/duplicate handling. **Impact: medium; effort M; risk low–medium.** Acceptance: unavailable/empty hubs fall back; no duplicate heading, broken title route or lost user order.
10. **Unify queue identity and handoff** (area 8). Durable logical queue/cursor, part boundaries and a loaded-window contract; retain working next-episode and local-channel behavior. **Impact: medium; effort L; risk medium–high.** Acceptance: restart, reorder, last item, stale end event, source failure and track carry-over work before shuffle/repeat expansion.
11. **Give approved chapters typed provenance** (area 6).
